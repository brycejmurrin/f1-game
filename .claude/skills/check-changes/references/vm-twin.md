# Move a browser spec onto the node gate (add a VM twin)

A browser spec costs SwiftShader minutes; a spec whose assertions are pure `__apex` reads can run in the Node VM instead. The substitution lives in `tools/ci/twinned-specs.mjs`; the evidence it is honest is a mutant. Reference: `docs/TESTING.md` §`vmPage`.

1. **Is it eligible?** `node tools/check/vm-portable.mjs --portable` lists portable specs (`--json`, `--blocked` for the rest). Eligibility is a static scan, not a verdict: a spec can scan green and still fail under the adapter (`understeer-cue` goes 0/7). The usual blockers are `requestAnimationFrame` in an evaluate body, in-page DOM driving, and `import { test } from "@playwright/test"` (moving that import onto `tests/helpers/fixtures.js` changes the browser run too: re-run the browser copy green in the same change).
2. **Run it unmodified under the adapter.** `APEX_VM_PAGE=1 node --test tests/specs/<file>.spec.js` (`tests/helpers/vm-page.js`). Every unserved DOM API throws a NAMED refusal; if the spec is not portable, stop here, and if the reason is permanent add a `BROWSER_ONLY` entry with the reason instead.
3. **Register it.** Add the spec to `ADAPTED` in `tools/ci/twinned-specs.mjs` with a one-line reason (test count, time vs the browser copy, the mutant id). A hand-written `*-vm.test.mjs` twin goes in `TWINNED` instead. `test:vm-page` (`tests/unit/adapted-specs.test.mjs`) then runs it in node, `select-specs` skips the browser copy on the blocking gate, and `partitionArgs` drops it locally.
4. **Add a fidelity mutant.** `twinned-specs.verify()` refuses an `ADAPTED` entry no row of `tests/data/mutants.json` names. A row is `{id, file, find, replace, why, spec, catchers}`: `find` is a CONSTANT in shipped code (never a line number), `replace` breaks one real mechanism, `catchers` names which tests must go red. A mutant that reddens every test proves nothing.
5. **Prove the twin bites.** `node tools/check/twin-fidelity.mjs --dry` checks the needles; `node tools/check/twin-fidelity.mjs <mutant-id>` patches, runs the twin and restores. `tests/unit/twin-fidelity.test.mjs` is the always-on half.
6. **Lower the debt.** `twinDebt` in `tests/data/ratchets.json` counts portable specs no `TWINNED`/`ADAPTED`/`BROWSER_ONLY` entry covers (`node tools/check/tree-counts.mjs --offenders` prints them). It is shrink-only with `slack: 0`: `node tools/check/ratchets.mjs --update` snaps it down (a generated file: never hand-edit).
7. **Verify once.** `node --test tests/unit/twinned-specs.test.mjs tests/unit/twin-fidelity.test.mjs tests/unit/adapted-specs.test.mjs`, then `node tools/ci/pick-tests.mjs`.
