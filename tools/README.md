# Apex 26 dev tools

Headless Node scripts for verifying and inspecting the game without a browser
window. Most pair with a **skill** in `.claude/skills/` (which explains when/how
to use them) — this index is the quick map. Run from the repo root. Disposable output never goes to `/tmp`: use `artifacts/tmp/` for batch logs/probes and `scratch/` for human-reviewed captures, renders, and profiles.

**Layers:** skill = when; this folder = the CLI; `apex_*` MCP = a **pinned**
subset (safe flags only). Which rows are wrapped, and which must stay CLI-only:
[`docs/AGENT-SURFACE.md`](../docs/AGENT-SURFACE.md).

### Test runner & coverage

| Tool | Does |
|---|---|
| **run-playwright.mjs** | The engine behind every `npm run test:*` — allocates a free port and port-suffixed report/artifact paths so independent test runs never share or tear down each other's web server. Forwards args to Playwright. |
| **pick-tests.mjs** | *"What do I actually have to run for THIS change?"* (`npm run test:pick`) — maps changed files to the `test:<group>` scripts that exercise them and prints a ready-to-paste command. The whole suite is ~40 minutes of software rendering; running nothing is how a regression ships. Rules live in `RULES` at the top and are deliberately biased toward running too much. `--staged`, `--since <ref>`, explicit paths, `--bg`. |
| **evaluate-scope-lint.mjs** | *A `page.evaluate()` callback may not close over Node.* Playwright does not CALL that callback — it serialises it, ships it to the browser and evaluates it there, so a module-scope `const` read inside is not a closure but a `ReferenceError` in the page, and the test then fails for a reason unrelated to what it asserts. `58614db2` did exactly this with two launch constants and killed every elevation track, four of which had been green; it read as a physics regression. Uses eslint-scope to flag free Node-side identifiers in `evaluate`/`evaluateHandle`/`waitForFunction`/`$eval`/`$$eval` callbacks. Browser and game globals are allowed; passing the value in as an argument is the fix. |
| **cache-bump-only.mjs** | *"Is this `index.html` diff JUST the cache bump?"* — the one exemption change-aware CI may make to its infra gate. `index.html` is infra (its script block IS the load order), so touching it forces a full run; but this repo's convention makes a `?v=N` bump the LAST commit of every shippable change, so the commit that gets reviewed is exactly the one where selection gives up. A `?v` rewrite is not a load-order change and is decidable. Pairs added/removed lines POSITIONALLY — line counts alone are not enough (`af05fa98` is +156/-156 and smuggles a real markup edit through), and a reordered script block therefore cannot pass as a bump. Exit 0 = pure bump, 1 = real change; `--json`. Fails toward running MORE on any ambiguity. |
| **test-observed.mjs** | *"Which tests have I never actually seen run?"* — the mechanical form of "a test that never runs is prose". Cross-references every Playwright test title DECLARED in `tests/specs/*.spec.js` (via espree, because nested describes decide a title and a regex cannot track block scope) against every title any log in `artifacts/logs/` has reported a result for. Three never-run tests were found by hand this session, each red for as long as it had existed; this finds the rest. `--by-file`, `--json`. NOTE `artifacts/` is local and gitignored, so the answer is "what THIS box has never run", not "what has never run anywhere" — a worklist ordered by ignorance. |
| **assert-audit.mjs** | *"And when it ran, did it CHECK anything?"* — the question that survives `test-observed`'s yes. A body with no assertion passes as long as the page does not throw, and reports as a green tick beside real tests. Grades every declared test `asserting` / `implicit` (waits on a condition, so a timeout is the whole assertion) / `vacuous`, and flags empty `.catch(() => {})` where a rejection becomes a pass. Follows helper functions defined in the same file — hud-audit's eight steer-mode tests assert only through `assertHud()`, and a body-only scan calls all eight vacuous, which is how a first version produced fifty findings of which ten were false. Capture harnesses whose product is a PNG gallery are allow-listed, not "fixed" with a bolted-on `expect()`. |
| **cross-file-paths.mjs** | *Every relative reference between files resolves to a file that exists.* Built for the `tests/` split, whose risk is a MISSED path rewrite rather than a wrong one. Most misses announce themselves; the ones that don't are the point — `fit-audit.mjs` and `menu-fit.mjs` import `../tests/helpers/f1-api-mock.js` inside `try { … } catch { /* degrades */ }`, so after a move the import fails forever, both tools quietly audit an empty data hub, and nothing goes red. Covers static imports, dynamic `import()`, `require()` and `new URL(rel, import.meta.url)` across `tests/` and `tools/`. Parsed with espree, not grepped: several test files build fixtures out of source text containing import statements, and a guard with false positives is a guard that gets switched off. |
| **ci-coverage.mjs** | *What does the deploy gate actually execute?* Reads `ci.yml` and resolves every `npm run test:*` and by-path invocation against the specs on disk, so it cannot drift from the workflow the way a comment does. Today: **2 of 110 Playwright specs**; 108 are gated by nothing before deploy. That is a deliberate choice — the full suite is ~40 minutes of SwiftShader — but it was previously visible only by reading four job definitions and expanding every npm script by hand, which is how `physics-characterization` sat in NO job through 175 commits of physics work. **A report, never a gate**: the obvious version (run `test-observed.mjs` in CI, fail on the never-observed count) is broken by construction, since `artifacts/` is gitignored and every title is legitimately unobserved there — the same environment-fact trap that reddened the guards job once already. `tests/unit/ci-coverage.test.mjs` guards the tool and pins the MECHANISM, never the number. |
| **select-budget.mjs** | *Can a change-aware CI job actually run what it selects?* TEST-AUDIT's CI design is blocked on gaps 7/8/13 and asks for exactly this: the budget re-derived against measured per-spec counts. Measured on CI run 31197770813 — smoke, 9 declared tests in 11m57s at one worker, so **79.7 s per test**. The term the design omitted is the cost of a FAILURE: `retries: 1` with `--timeout=240000` makes one timing-out test cost **480 s**, so a 15-minute budget holds 11 tests all-passing but only **6** if it must survive a single timeout — the step dies exactly when the selection finds something. Median spec is 6 declared tests and the largest is 117, which settles per-spec over per-group by arithmetic rather than by preference. Also models the lever: dropping the retry buys almost as much as doubling the budget, because the selected gate should report a failure promptly instead of retrying until its budget is gone. `tests/unit/select-budget.test.mjs` guards the MODEL, not the constants — and caught a real defect in this tool on its first run (a missing file threw ENOENT instead of returning null). |
| **select-specs.mjs** | Per-SPEC change-aware selection for the blocking CI job (`selected` in ci.yml). Decomposes `pick-tests`' groups into their spec files, orders smallest declared-test-count first, and cuts at `select-budget`'s measured capacity surviving one timeout at the selected-gate settings (retries 0, 120 s/test). NAMES every spec it skips — silent truncation would read as "covered". `tests/unit/select-specs.test.mjs` guards the glob expansion, the cut, and that these settings fit more tests than smoke's retrying gate settings. |
| **select-recall.mjs** | *Would the selector have caught it?* Replays `select-specs` against a history of REAL regressions (the side-flip, the vegas barrier, the audio-panel extraction, the input net, a narrow-helper change) and asserts the spec that actually reported each one is selected — or honestly named as infra/unaffordable. Judges faulty-CHANGE recall, the metric Facebook's Predictive Test Selection reports separately (>99.9% of faulty changes vs >95% of individual failures) because a bad change is usually caught by several tests. Found a real routing bug on its first run: `js/track/tracks.js` holds buildProps but did not route to `scenery`. A SILENT miss fails the guard; being unaffordable does not. |
| **tests-split.mjs** | *The `tests/` split, as a reproducible plan rather than an 18-item checklist.* `AUDIT-SYNTHESIS §R2` lands as ONE commit across ~175 files and five of its lockstep items are marked ⚠ "no guard turns red" — a missed rewrite there is green, not broken. So the rewrites are **derived from the tree**: the same espree reference extraction `cross-file-paths.mjs` uses, resolved through the move map and recomputed from each file's new location, which finds references no checklist listed. String paths (package.json's scripts, `read("tests/…")`, docs) get a second, deliberately narrow scan. **History is never rewritten** — `docs/archive/`, `docs/research/` and `.claude/workflows/` describe the tree as it WAS, and the first plan would have falsified 700+ lines of it. `--json`, `--apply`; the default is a dry run. |
| **wait-polling-lint.mjs** | *A declared timeout that cannot fire is not a bound.* Playwright polls a `waitForFunction` predicate on `requestAnimationFrame` by default, and a page running the game loop under SwiftShader starves that poll so badly the timeout never gets a turn — MEASURED at **109,665 ms against a declared 3,000 ms**. Only a THROWING predicate terminates promptly (11 ms), which is why the same wait behaves completely differently depending on whether a backend happens to be installed. Flags `waitForFunction` calls carrying a timeout without `polling`; `waitForSelector`/`locator.waitFor` are driven by the mutation observer and are not exposed. A RATCHET at 382 sites (312 under `tests/`, 70 under `tools/`), not a sweep — rewriting them all in one commit would be a 300-site behavioural change with no run behind it. Scans any `.js`/`.mjs`/`.cjs` under `tests/` and `tools/`: it admitted only `.js` for months, so the whole `tools/` half of its own scan list was invisible. |
| **test-bg.mjs** | Starts test groups in the BACKGROUND and hands back a log to tail (`npm run test:bg -- smoke`). **Default is sequential** (one group at a time); `--parallel` restores the core-capped concurrent start; `--wait <groups>` chains start→wait→next. `--status` / `--stop` / `--tail <group>`. Logs start/end timestamps, duration, pass/fail and loadavg to console and each `artifacts/logs/<group>.log`. Restarting a group that is still running KILLS the old process group first — dropping its state entry while it lived left an invisible run interleaving output into the log the new one had just truncated. |
| **tooling-fast.mjs** | Sequential runner for `npm run test:tooling-fast`. One unit file at a time via `node --test --test-concurrency=1`, with per-file start/end/pass/fail/duration (+ loadavg) on stdout and `artifacts/logs/tooling-fast.log`. Exports `TOOLING_FAST_FILES` (coverage-audit source of truth). |
| **test-coverage-audit.mjs** | Coverage guard (`npm run test:audit`) — every `tests/specs/*.spec.js`, `*.test.mjs` and `*.test.cjs` must be reachable from at least one topical `test:<group>` npm script, so a pre-push group run can't silently skip a test. Exit 1 if any is orphaned. |
| **layout-audit.mjs** | **One CLI** for menu geometry + PNG/DOM capture. Default: geometry matrix (clip/tap/overflow). Flags: `--gallery` (fast PNG+DOM, resumable, `--jobs`), `--screen=ID` (one cell), `--survey` (title-path recipe), `--list`, `--report`, `--shots`, `--dom`, `--force`. Catalog: **menu-screens.mjs**. Engine: **menu-capture.mjs**. Output: `artifacts/layout-audit/` (geometry) and `artifacts/layout-audit/gallery/` (gallery). See docs/LAYOUT-AUDIT.md. `npm run ui:audit` / `ui:gallery` / `ui:survey`. |
| **menu-screens.mjs** | Canonical `SCREENS` + `VIEWPORTS` + `OVERLAY_IDS` (library). |
| **menu-capture.mjs** | Library: `runMenuShot` / `runMenuGallery` (not a CLI). |
| **mcp-cli.mjs** | ONE layout question, interactively, against a running build — the interactive complement to layout-audit's matrix. Spawns `tools/chrome-devtools-mcp.sh run` over stdio JSON-RPC (same wrapper as `.mcp.json` / `cdmcp-cli.py`), so it reaches the browser even when the session's tool list does not carry `mcp__chrome-devtools__*`. ## Subdirectories (R3 families)

Four self-contained families live in subdirectories; everything else stays
flat (manifest.cjs, carview.html, the test infra and every baseline/audit are
deliberately NOT moved — their consumers hardcode the flat paths):

- `net/` — WebRTC/Nostr end-to-end harnesses: rtc-e2e.mjs, rtc-e2e-3p.mjs, rtc-e2e-room.mjs, nostr-local.cjs, nostr-probe.mjs, turn-local.cjs
- `car/` — car renders: render-car.mjs, carshot.mjs
- `capture/` — frame capture: apex-capture.mjs, backend-compare.mjs, baked-scenery.mjs, motion-capture.mjs, shot.mjs
- `lighting/` — ab-lighting.mjs (lighting-campaign/ was already its own package)

## Conventions

- **The capture tools are a family, not duplicates.** `apex-capture.mjs` is the
  canonical parallel sweep (cameras/modes/tracks/identity/lap-tour);
  `carshot.mjs` is the ~5 KB cropped studio probe and `render-car.mjs` the full
  contact sheet. The one-off variants that WERE redundant with it —
  `shot-sweep.mjs` (logged sweep), `chase-shots.mjs` (chase-cam lap ring),
  `track-sweep.mjs` (JSON-only sweep), and earlier `shot-car.mjs` /
  `photoshoot.mjs` / `migrate-output-layout.mjs` — have been deleted; recover
  any of them from git history if a need returns. `menu-fit.mjs` survives
  `layout-audit.mjs` only because `--safe=` simulates ARBITRARY notch insets,
  where layout-audit injects only its fixed, per-viewport measured ones —
  headless Chromium itself reports every `env(safe-area-inset-*)` as 0, so
  both must simulate.
- **Surveying a track:** `survey-track.mjs <id>` is the one-stop pass (shots +
  flagged probe). Add `--oblique` for a bounds-fitted topdown plus N/E/S/W
  high obliques. For a one-off framed shot use `tools/capture/shot.mjs`;
  for a parallel multi-track screenshot sweep use `apex-capture.mjs`; for a quick
  numbers-only terrain re-probe use `.claude/skills/survey-track/ground-profile.mjs`.
- **Chromium:** prefer `CHROME` / `PW_CHROMIUM`, then `/opt/pw-browsers/...`
  when present; otherwise Playwright's bundled browser. Servers bind a free
  port (or `:3456`).
- **Two Playwright packages on purpose:** the spec suite runs on
  `@playwright/test`, while ~20 tools here import bare `playwright` (the
  library) at module scope for direct browser control. Removing either breaks
  the other's consumers, so `package.json` carries both.
- Anything that edits `js/*`/`css/*` still needs a content-hash refresh (`node tools/bump-cache.mjs --apply`).
- Never write disposable output to `/tmp`; use `artifacts/tmp/` or the standard `scratch/` subtrees.
- `rtc-e2e.mjs` — a REAL WebRTC handshake between two pages (`npm run rtc:e2e`).
  Covers the one path nothing else can: the loopback transport has no SDP, and
  the lobby spec uses a fake transport because a real `RTCPeerConnection` never
  finishes ICE gathering in a sandboxed CI browser. Deliberately outside every
  test group — it takes minutes and depends on the host's network stack. Run it
  by hand after touching `js/net/handshake.js` or `js/net/transport.js`.
- `rtc-e2e-3p.mjs` — THREE real WebRTC peers in one room, which is the only
  thing that can test the multi-peer path: the loopback transport has no SDP
  and the lobby specs use a fake one, so `test:net` cannot see it. Checks that
  a second invite does not drop the first guest, and that guest B can see
  guest C — which is only possible via the host relay. Run by hand
  (`npm run rtc:e2e-3p`, or `rtc:e2e-3p-relay` to force every pair through
  TURN — the leg a developer never exercises and a phone behind
  carrier-grade NAT always does).
- `nostr-local.cjs` — a Nostr relay on localhost, so the ROOM CODE path can be
  tested without depending on somebody else's server. The smallest relay
  Trystero needs (ephemeral events, `since: now()`, live fan-out only). Needs
  `npm i --no-save ws`. `--reject` makes it a HOSTILE relay — every publish
  comes back `["OK", id, false, "blocked: …"]`, as a real spam policy does —
  and `--reject-after=N` accepts N first, which is the shape of a rate limit
  rather than a ban. Without that mode the code that DETECTS a refusal had no
  test at all, because the only relay we can run accepted everything; and a
  refusal is invisible from outside, since Trystero turns it into a
  `console.warn` while the socket stays open.
- `rtc-e2e-room.mjs` — drives the ROOM CODE path end to end against that relay
  (`--peers=3` for three). The only test of `exchange()` there is: the loopback
  has no SDP and the lobby specs use a fake transport, so four regressions
  shipped through that gap before this existed. Against a relay we run, a
  failure is ours by construction rather than somebody's server having a bad
  day. Needs `tools/net/nostr-local.cjs` running. `--delay=SECONDS` makes the host
  sit on its offer before any guest joins, which is what a human carrying a
  six-character code across a room actually does — the harness otherwise joins
  within a second of hosting and cannot model it. (Measured: 45 s still
  connects, so offer staleness is NOT what breaks room codes on real
  hardware.)
- `nostr-probe.mjs` — which public relays will actually CARRY our signalling.
  Publishes what the game publishes (ephemeral kind-22xxx, freshly generated
  key) to each candidate and records the NIP-01 verdict. This is the only
  criterion that decides whether room codes work: relays increasingly refuse
  anonymous ephemeral events, and all six of the shipped list pass
  reachability, popularity and uptime while room codes still fail. The list has
  been changed three times on reasoning; change it on this instead. Prints a
  paste-ready `RELAYS` block and exits non-zero if nothing accepts. Needs
  `npm i --no-save ws @noble/curves`.
- `turn-local.cjs` — a TURN server on localhost, which is what makes that relay
  mode testable at all: on one machine ICE forms a direct pair instantly and
  TURN is never touched. Needs `npm i --no-save node-turn` — a test fixture,
  deliberately not a dependency. See its header for a known, unattributed drop.
