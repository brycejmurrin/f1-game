# Bug hunt 2026-10-09 — findings and fix plan

**What this is.** A read-only hunt over the whole `js/` tree at `64dd7a8` by
thirteen parallel reviewers (one per domain slice), each briefed with
`docs/BUGS.md` and `docs/notes/DEFECT-LEDGER.md` §7 as the do-not-re-report
list. Every finding below names its `file:line`; the ones marked **verified**
were re-read in source by the coordinating session, and the ones marked
**repro** have a Node/VM script that shows the failure. Nothing has been fixed
yet. This is the plan to agree on before any PR opens.

**Scope note.** The reviewers fuzzed the arc-bucket broadphase (1.6 M queries),
`ContactGeometry.sweep` (168 k), `AiCorridor.crosses` (300 k), the scenery
frame/shift transforms (15 k node cases) and `TyreModel` at every `dt`, and
found them clean. The start-line wrap, sector timing, pooled AI ctx objects,
curvature channels, store mirror/revision machinery, net authority rules and
the three renderers' resource lifetimes were traced and are sound. What is
left is edge-case lifecycle glue, a few unvalidated inputs, and some per-frame
waste.

**Severity key.** high = common path broken / data loss; medium = wrong
outcome on a reachable path; low = cosmetic or rare.

---

## How to land it

- One PR per batch below, on a `cursor/<topic>-<hash>` branch, opened as a
  DRAFT into the ship branch (AGENTS.md rule 12). Batches are cut by subsystem
  so each stays inside one lane; `js/game.js` edits need
  `node tools/ci/who-is-on-it.mjs --claim` first.
- Every fix lands with the unit test named beside it (most are `*-vm.test.mjs`
  twins that run in `test:tooling-fast`). The browser group per batch is what
  `node tools/ci/pick-tests.mjs` names, capped at two.
- Batches 1–4 are the ones worth doing first: each is small, verified, and
  player-visible. Batches 5–8 are real but lower impact. Batch 9 is perf.
  Batch 10 needs a product/physics decision before code.
