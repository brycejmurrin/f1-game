## Historical code and verification contracts

The rendering cluster joins S02–S05 and S08. Capture success requires the relevant renderer's actual presentation, valid scene pixels, source freshness and restoration of render ownership. A selected backend is insufficient: S05 found a requested TLX preference silently bound to GLX and describes a later test guard for the bound renderer. S02's capture ratios are three-run software-host samples, while S05's native-error injections and constructor rollback tests establish correctness without establishing FPS savings.

S03 counts allocation requests, excluding compositor surfaces, native residency and deferred loads. S08 measures post-GC JavaScript with track-build identity and resource completeness; overlapping CDP memory categories cannot be added into one total. S08 cites `tests/unit/diagnostics-tools.test.mjs` and `tests/unit/mem-census-growth.test.mjs` as falsifying controls, and distinguishes rounded MiB legacy fields from raw-byte budgets. Neither census proves absence of all leaks or player-device performance.

S04 is an architectural idea ledger rather than a shipped-feature list. Its useful durable constraints are three-backend parity, licensing/budget checks for imports, deterministic mathematical comparisons where appropriate, and hardware validation for sampling, anisotropy and timing. Recheck current module ownership and shader locations before extracting any proposal.

The HUD chain is S13 → S14 → S10 → S11/S12. It traces the shift from independent floating slots and fixed offsets toward measured placement, followed by independent user arrangement and editor usability. Survey findings must distinguish shipped settings, all-on stress cases, real fit ticks, forced transient DOMs and expected-visible false positives. Historical test contracts include idempotent fitting, hiding a piece never increasing required space, actual painted control clearance, zoom-consistent offsets, valid anchor ordering and preserved forced-colors widths. S12 explicitly keeps the monotonicity threshold; S14 calls for numerical or rectangle intent checks instead of replacing one source-string assertion with another.

S01, S06, S07 and S09 explain harness evolution. S01's parallel-merger/game-slot procedure is superseded by today's GitHub landing contract in WORKERS and AGENTS. S06's API probes do not authorize new calls or establish current access; inference credentials did not expose session history or management billing. S07 distinguishes applied prose/routing fixes from deferred behavior changes. S09's hook dispatch details describe the observed harness of that date, including its stated uncertainty.
