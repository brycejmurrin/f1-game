## UI findings and amendment order

Sources 1–2 preserve a substantial difference between green tests and demonstrated contracts. The first report describes 30 passing unit files, thirteen browser specs, source-only CSS checks, missing execution of pause-resume countdown and title/picker handlers, copied touch rules, and vacuous geometry waits. Its ranked findings include raw strings written into a JSON-backed steering preference, async wait predicates, old appearance defaults pinned in most HUD cells, first-declaration CSS inspection standing in for the rendered cascade, conditionally skipped keyboard checks, and optional mirror pixel checks. These are historical reviewer claims, with confidence and unverified dependencies retained rather than promoted to current bugs.

Source 2 supersedes three open run rows. Photo Studio passes 5/5 alone in 286 seconds after a loaded-run geometry failure; the reviewer calls it flaky/load-sensitive while explicitly noting that one pass cannot prove immunity. Mirror remains 2/3 alone: TLX reaches the 300-second timeout again on SwiftShader, with no assertion error, and is classified environmental on that machine. GLX passes close to its budget. The HUD tail passes 15/15 after 37 earlier passes, but overlaps one prior test and does not recover the exact original missing member. The stated all-51 result is therefore a union claim with an explicit accounting caveat, not a single clean full run.

The continuation adds manual browser-logpoint reachability for HUD fitting and paused Photo Studio; the desktop pedal probe does not hit a touch-only target. Nine named specs still lack a browser-debugger pass. Neither document demonstrates every spec's own Playwright flow at a breakpoint. Their proposed new timeouts, layout-settle waits and phone probes were recommendations, with no test or product edits performed by those reviewers.

## Producer and data contracts

Source 3 maps each 17-field tuple into a JSON finding, rejects duplicate IDs and dangling duplicate references, and excludes duplicate rows from ranking. Score combines severity, confidence and player/pipeline/hygiene impact, subtracts for unverified rows without confirmation, adds a confirmed-tree bonus, and adds a hidden-bug bonus. The prose formula it emits omits that hidden-bug bonus, a historical transparency limitation. It counts lane ownership and rejects repeated or unknown IDs, but missing ownership is reported in generated prose rather than asserted away. It emits status, top 25, pattern counts, subsystem gaps, verification notes and lane plans; it relies on status.py and other row inputs outside this assignment.

Source 4 supplies goals, owned globs, finding IDs, batch readiness, verification recipes, effort, dependencies and optional PR slices. Its final state is produced by ordered mutations, not only the initial list. Dynamic file ownership derives from normalized findings and selected late folds omit product paths. Dependencies distinguish debugger preload from later filename migration, canary splitting before backend/performance edits, and lint introduction after existing violations are removed. Later folds update platform timeouts and portrait-layout classifications. Some earlier draft wording survives in goal/dependency strings; generated readiness also depends on status.py, so individual historical sentences do not establish a lane's final or current state. Claimed disjoint ownership is a planning intention: source 3 validates finding ownership, not glob intersections.

Source 5 selects mapped comments, emits URL/date/author/status wrappers, retains later-part supersession text and normalizes hypothetical filenames using tracked basenames and filesystem existence. It reads comments.json and reportmap.json and consults Git metadata. This is an offline historical materializer, not a game-runtime importer. Source 6 records amendments, partial continuations and final continuations as separate records; original issue comment IDs are the durable join keys.

Source 7 defines the shared tuple schema and imports batch row sources by reading and executing their Python text with reviewer constants supplied. Its defects cover camera corner fixtures, renderer canary source windows, lighting resolver replicas, absent finite-number checks, conditional geometry gates, shader compilation limits, XR fallbacks, wall contacts, agent determinism and asset error observation. The debugger rows distinguish inability to attach Node targets, absent absolute VM filenames, the Node 22 flag spelling, shadowed logpoint variables and deferred-script URL mismatch. References to PR #2967 and issues #2960–2962 describe the state recorded then, not newly checked resolution.

Source 8 records the audio contract more precisely than an all-pass headline: fixed running contexts, frozen clocks and failed decoding prevent suspended-context/sample paths; fake parameters immediately apply ramps and do not preserve routing connections. Other rows target unused distance-falloff spies, search results never shown populating, typo-permissive API proxies, missing IndexedDB and authentication failure paths, and untested output reaching the destination. Its A1-15 duplicates DBG-01. Some synthesis checks are only partial, and debugger hits are unions of racy manual passes; unobserved paths are explicitly probe limits.

Source 9 preserves per-batch verification distinctions before the findings: race-1 ran 49 units without mutation experiments; UI-2 had incomplete/unclassified browser runs; car-2 had no debugger pass and mostly subagent reads; modes-1 ran 46 files but only one spec was driven through browser logpoints. Findings repeatedly separate real module calls from copied arithmetic, unconditional assertions from conditional escapes, and visible rendering from source-string presence. Source 9's earlier UI classifications must be read alongside source 2 and later row amendments outside this assignment.
