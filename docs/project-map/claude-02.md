Memory restore is called by session-start. Policy and parser helpers have no independent hook registration: their guards import or invoke them. Cursor edit and shell adapters also invoke the file-protection wrapper. Codex does not run these Claude hooks automatically, per the root contract.

## Failure behavior and limits

Browser payload parse failure blocks. File-protection payload/parser failures explicitly warn and allow, even though the registry blocks nonzero hook failures: a deliberate exit 0 remains an allow. Post-edit, navigation, session readiness and memory sync are advisory. Shell strict parse failure reports a null status for the outer Bash guard's fallback; malformed trusted runner calls block because the hidden leaf cannot safely be inspected.

Parser recursion is bounded: shell bodies below depth four, alias expansion below depth two, trusted runner unwrapping at eight, and package/browser recursion below depth three. It is a conservative shell reader, not a general interpreter. Dynamic target expansions, interpreter filesystem writes, patch/apply and directory/glob restoration remain documented extraction limits; the next batch must reconcile the older top-level download-output gap claim against the newer dedicated write reader. Literal GitHub HTTP inspection is heuristic. Closed-PR lookup errors allow; no lookup was executed here.

Agent identity predicates differ intentionally or historically: the browser guard considers agent_type alone sufficient, while hatch creation protection uses agent_id/transcript identity. Read-only reporter git mutation matching uses raw regex; target extraction supplies separate filesystem scope enforcement. These are boundaries to inspect before broadening enforcement claims.
