## Generation order and ownership

`package.json:46–49` is the executable aggregate contract. `gen` runs circuit metadata → shell → title art → test scripts → Cursor rule mirrors → `gen:docs`. `gen:docs` runs tools README → slider documentation → hooks table → flags table → architecture table → coverage table (outside this directory) → agent index (outside this directory) → output catalog → locales. Hooks and flags share `docs/DEBUG-HOOKS.md`, so their block writers run serially. Locale collection runs after shell generation because it scans `index.html`. `gen:check` additionally validates changelog fragments; changelog folding is a separate `fold` command, never an ordinary aggregate rewrite.

The namespace is wider than deterministic generated files. Asset bakes, exported-preference application, Blender authoring, network downloads and browser captures are manual authoring commands. `--check` means different things across tools: byte equality for doc/shell generators; semantic validity for garage/settings defaults and changelog fragments; hash integrity for vendored three; MP3 shape/bitrate for soundtrack compression. A successful validity check does not establish that a manual output matches an original export.

The source of generated-file ownership is the writer, not a blanket directory rule. `gen-shell` owns selected shell/service-worker blocks plus whole `js/roster.js` and `cockpit-view.html`; `title-art` independently owns another block in `index.html`. Existing handwritten surrounding content is required by block writers. `tools/lib/generated-paths.mjs:13–26` is a narrower merge-regeneration list (whole files safe for automatic conflict repair), deliberately excluding authored `index.html`; it is not a complete list of every generated artifact. `.claude/hooks/protect-files.sh:6–13` distinguishes outright protected files from marked blocks and generated docs checked for drift.

The shared model serializer `writeAX26` (:592–638) chooses v2 when vertex count≤65,535, colors fit 0–1, and material IDs are integral bytes; otherwise falls back to v1. Header is 20 bytes with AX26 magic, version, vertex and index counts. V1 uses float position/normal/color/material arrays (40 bytes per vertex) and uint32 indices. V2 uses float position, snorm16 normal, RGB8 color and byte material (22 bytes per vertex), uint16 indices. The importer delegates to this exact serializer, while tree baking deliberately uses `tools/lib/pack-assets.cjs` v3 with fractional sway material support. `assets verify` accepts only v1/v2, so the artifacts/trees v3 path is not interchangeable with the regular model-pack validator.

## Proven comment and behavior mismatches

These are static discrepancies with both sides identified. They are recorded for future review; none was fixed or reproduced by executing a generator.

1. **Flyby full-list bake loses accepted conditions.** `bake-flyby.mjs:68–77` accepts `when:{night,wet}` and :83–85 presents the bake as the paste side of the editor's validation contract. Yet `render` at :160–169 serializes only id/dur/ease/eye/look/fov. A validated conditional shot becomes an unconditional shot in generated DEFAULT. The tool's whole-list promise (:17–24) does not preserve all accepted shot data.
2. **Flyby comment-preservation promise is broader than implementation.** `bake-flyby.mjs:178–184` says lead comments include block comments. `shotNotes` at :188–196 only collects trimmed lines beginning `//`; `/* … */` lines are discarded. Matching-id line comments survive; arbitrary block comments do not.
3. **Tree mover does touch generated blocks.** `move-tree.mjs:18–20` lists generated @gen-shell blocks among content it does not touch. The actual sweep at :140–152 applies token replacement to whole swept files, with only manifest MOVED protected; no @gen-shell parsing/exclusion exists. Later gen-shell regeneration (:230–232) repairs its own blocks in apply mode, but the sweep/plan does include them. Title-art is not regenerated by this post-move gen-shell call.
4. **Path boundary regex contradicts its own `.js.map` example.** `move-tree.mjs:79–81` promises `.js` tokens do not match `.json` or `.js.map` siblings. Its right boundary at :90 excludes letters/digits/underscore/hyphen, but not dot. Thus a source-map filename contains a match for the configured source prefix ending in .js; `.json` is excluded because the next character is `o`, whereas `.map` is not. Same right boundary is reused for leftovers (:167).
5. **Elevation authoring guidance bypasses the actual shell contract.** `bake-elevation.mjs:40–41` and :377 instruct adding a numeric-version script tag by hand. `gen-shell.mjs:7–13,27–31` owns the roster-derived shell and uses literal `dev`; `tools/manifest.cjs:206–210` already includes the generated elevations. The obsolete instruction also cites `tracks.js` as home of the authored-bump suppression (:29–30); it now lives in `js/track/core/def.js:212`.
6. **Elevation header's fixed bacinger count is stale.** `bake-elevation.mjs:14–15` says 24 circuits in MAP; :55–67 contains those 24 plus nurburgring and portimao. No-argument bake iterates all 26 keys (:341–343). The generated header at :367–369 attributes all output to bacinger traces although explicit OSM requests are supported and can be merged into that same table (:295–309,360).
7. **Doc-target inventory description overstates coverage/order.** `targets.mjs:2–3` says TARGET of every gen-*.mjs; :18–19 says gen:docs order. Its explicit list (:20–29) omits gen-locales, moves output-surface to second position, and includes neither all gen-* tools nor all their outputs. Actual npm order is `package.json:49`, with output-surface near the end and locales last. The hook consumes this limited list at `.claude/hooks/bash-guard.sh:581`; it should not be read as exhaustive artifact ownership.
8. **Defaults `--check` is not equality drift.** Both defaults tools' @doc lines (:2) say check reports drift, but garage check (:103–115) only validates metadata/key shape/count; settings check (:210–220) only validates SPEC membership/adaptive/subsystem policy. Neither accepts/compares an export in that mode. Values can differ from a previous export while check passes. Settings header (:9) says file agrees with SPEC, but equality to SPEC default values is not checked.
9. **Settings force/include are not persisted check exceptions.** `settings-defaults.mjs:173–178` allows explicitly forced adaptive or included subsystem overrides, as described in the header. `check` at :217–218 rejects those same keys unconditionally. A deliberately accepted authoring operation can therefore create a file rejected by its semantic check; the override controls do not change the check contract.
10. **Asset bake is exercised by ordinary tests despite header.** `assets.mjs:5–6` says never run by a normal test pass. `tests/unit/assets-pack.test.mjs:1217,1338,1397` explicitly spawns bake-synthetic, bake-synthetic-models and bake-model in fixture paths. The author-time/runtime separation remains true, but the test-pass claim is not literal.

An authoring report's budget number can undercount what `verify` enforces. This is a limitation of the report, not evidence that the current pack exceeds budget.
13. **Importer scope text understates transform traversal and skip visibility.** `import-models.mjs:16–18` says one level of node transform; implementation recursively composes node chains at :220–222,269–272. Header :20–22 promises unsupported data is skipped with reason; non-triangle primitives are silently continued at :225, and skins/animations are not explicitly refused at traversal.
