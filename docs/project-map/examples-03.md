Its complete JSON parses into verdict, source, viewport, reducedMotion, requestedBackend, quality, scale, scenes, variants, captures, checks and patches. Eight scenes cover seven Bahrain lighting/weather combinations and Monza night rain. Fourteen variants comprise Original, Clear and four smoke colors at three strengths. The catalog intentionally mixes two capture record shapes. Fifty-six original entries carry PNG and WebP hashes plus encoded byte counts. Fifty-six wet-weather refresh entries carry computed visor state, a detailed captured game identity and a sha256 field instead. The latter describe Bahrain wet daylight, rain at night, storm daylight and Monza rain at night. They retain camera, race state, renderer, software-presentation, frame timing, wetness, rainfall, lights, post-processing and tuning inputs. These counters describe capture provenance and cannot establish current performance.

## UI and consumer flow

Supplemental text reads of index.html and app.js establish the consumer. index.html links style.css and defers app.js. The application fetches shots.json, rejects a non-PASS verdict, builds a scene/variant lookup and generates scene options/cards. The default is Bahrain dry daylight with amber medium tint. Selecting scene, visor mode, color or intensity looks up Original plus the candidate, decodes both images, and updates the stage only if the request generation remains current. Failed images produce a status message. It updates the download, selected states, descriptions, caption and all scene thumbnails; color/intensity fieldsets disable outside smoke mode.

The native range updates the --wipe percentage and accessible value text. The stylesheet clips the candidate image from that position and aligns the visible divider. Selector visibility toggles the hidden panel, body class, aria-expanded and button text; the initial selector is hidden at widths up to 1100 pixels. Cards scroll to the comparison with reduced-motion-aware behavior. The viewer discloses the capture source and refresh source in its provenance details. It does not start the game, mutate game settings, persist selections or own an animation lifecycle.

style.css provides dark tokens, system-font fallbacks, lime selection/focus states, the two-column selector/stage, image labels, four-column scene cards, notes and footer. Disabled fieldsets fade. Keyboard focus includes the transparent full-stage range through :has(). Responsive rules at 1600, 1050 and 760 pixels are followed by later widening and selector rules: maximum content width becomes 1920, horizontal padding becomes clamped, selector width becomes 240, and up to 1100 pixels the stage and controls occupy separate rows. At 760 pixels the layout is stage-first flex with a controls grid and two-column cards; at 600 the action hint hides. The later rules matter when assessing the final cascade. Reduced motion disables smooth HTML scrolling. The CSS contains no downloaded font, image URL or import dependency.

## Assets, export and limits

The local capture inventory contains eight originals, while the additional variant images and thumbnails declared by the catalog are intentionally retained in an existing gallery output. The exact 104 absent full-resolution and 112 absent thumbnail references appear only in examples-03-evidence.json. README explicitly says an empty export cannot reconstruct the static 112-shot gallery; the animated optics view uses the eight originals after runtime aliases are exported.

visor-lab-export.mjs copies these authoring catalogs and CSS together with the surrounding demo files and image directories. It preserves destination-only comparison pairs by ID and refreshes visor runtime aliases from game sources. It does not delete old gallery assets or generate the missing static variants. No original static capture generator is established by the inspected references; the adjacent A/B tool belongs to the separate comparisons catalog. No group file declares image licenses, and capture hashes/source metadata do not supply a license grant.
