## Historical renderer contracts and decisions

S01 identifies shader duplication as the central maintenance cost: Lit and Composite carry most visual identity, while even the original GLSL duplicated noise functions. It chooses small named JS string chunks for noise, BRDF and tonemapping under the no-build IIFE/static-hosting constraint. It rejects a runtime regex GLSL-to-WGSL converter because sampler splitting, bind groups and strict typing require compiler semantics; a touched-both-files check cannot establish semantic parity. Named chunk siblings reduce drift but do not make language-specific shader trunks a single source.

The review marks shared GLSL chunks and a modular GLX split as executed variants of its proposals. Remaining historical proposals document the draw interface, centralize the stride-15 light layout, enumerate full draw-state combinations, describe render targets through shared allocation/free logic, and consider instancing only after profiling proves draw-call pressure. It emphasizes preserving shared context, load order, state-cache shortcuts and bind-before-delete memory discipline. Pixel parity cannot demonstrate absence of a mobile memory leak.

S01 disputes S02's sequencing: the returned renderer object already defines the seam, so internal refactors yield benefits before an async façade rename. Lit/Sky must precede Composite because the latter consumes scene color and depth. The default WebGL path should avoid paying async initialization costs merely to support an opt-in backend. These are historical recommendations, not a present implementation backlog.

S02 inventories seventeen old shader programs, loose uniform arrays rather than UBOs, then-current lack of MRT/instancing, target formats and fallbacks, queried MSAA capped at two samples and disabled on mobile, and a depth texture read with both comparison and ordinary samplers. Old line citations describe a monolithic layout; amendments explicitly say shader strings later moved into shared chunks and shader modules.

The historical light record is fifteen floats: position, color, radius, direction, inner/outer cone, bleed, volumetric weight and glare weight. The migration proposes padded four-vector WebGPU records and named byte offsets. Its frame protocol is shadow begin/casts/end, optional environment faces, begin, sky and object draws, then present. Resource creation/freeing, target lifecycle, shadow and environment methods form the same backend surface; frame and present option shapes must remain compatible.

WebGPU mappings include split texture/sampler bindings, comparison samplers, uniform/storage buffers, explicit passes and load/store operations, MSAA resolve targets, immutable pipeline variants for blend/cull/depth/alpha-write states, dynamic per-draw uniform offsets, indexed buffer layouts and vertex-index fullscreen triangles. Async device acquisition, resize/DPR handling, device loss, fallback and an observable backend hook complete the proposed seam. The document's original sample selection logic and its later opt-in status prose represent different eras; neither is a current selector specification.

Its phases progress from façade to device/clear, Lit/Sky, shadows/environment, post effects and instancing. Historical validation asks for unchanged WebGL visuals, positive backend boot signals, deterministic parked poses across tracks/day/night, lighting and wall probes, per-backend golden images and measured frame time. Risks include shader drift, doubled testing, mobile NaN guards, async boot and uncertain payoff. Older crash-prone phones would gain nothing from WebGPU; WebGL memory budgeting, LOD and measured instancing could help them. The later status amendment supersedes the original recommendation to stop after Phase 0. Current AGENTS additionally identifies TLX as default, so the archived WebGL-default statement is dated.

## Historical audit workflow contracts

S03 defines structured schemas for at most eight findings per auditor, move clusters with full lockstep edits, skeptic verdicts and feasibility gaps. Five finding auditors inspect the cleanup diff, unapplied survey items, docs against code, guard health and fresh structural mess; a sixth auditor surveys restructuring. Prompts mention camera façade wiring, physics-constant completeness, removed agent aliases, stale documentation, vacuous assertions, ratchets and path assumptions. Proposed test/tool moves, naming changes and extractions are candidates requiring evidence, not an approved migration.

The orchestration pipelines finders, skeptically verifies only BUG and INCOHERENCE findings, and accepts other kinds as explicitly unverified. HIGH findings receive correctness and reproduction lenses and are killed only when all nonempty votes refute; LOW findings are killed by any refutation. Consequently an empty vote set survives as confirmed, a useful limitation when interpreting any downstream output. Move feasibility separately reads manifest, test/config and documentation dependencies. Synthesis removes refuted findings and requests exactly FIX-NOW, RESTRUCTURE and DEFER sections, returning synthesis, retained findings, clusters and refutation count.

The source assumes a host provides phase, log, agent, pipeline and parallel functions. Its temporary scratch location, old repository checkout, branch/tip, old flat tool references, file counts and strict read-only audit instructions belong to that session. Reading this source does not establish that the workflow ran or that any proposed defect survived actual code review.
