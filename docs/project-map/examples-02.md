## Page and adapter contracts

index.html defines the static gallery's DOM contract: scene selector, visor mode, four colors, three tint intensities, paired original/candidate images, native wipe range, download, scene grid, status and provenance. It loads style.css and app.js and connects to the animated and captured-pair viewers. The labels describe a fixed view with 12/18/24 percent tint; those are presentation claims about captured variants. The inline SVG is a decorative brand mark.

Supplemental app.js inspection establishes the data flow: fetch shots.json, require verdict PASS, build a map keyed by scene plus variant, then decode both selected files before swapping either visible image. A generation counter prevents a late request from replacing a newer choice. Smoke combines color and intensity; off and clear are standalone variants. Rendering updates pressed state, disabled fieldsets, alt text, full-resolution download, captions and lazy grid thumbnails. Selector hiding preserves the selected lens. An unsuccessful image load reports a status instead of committing a partial pair. The committed authoring directory intentionally holds only eight originals; README.md says the other static gallery captures must be retained in an existing gallery export.

optics.html contains both layout and executable demo glue. A baseline canvas holds the original; the game canvas, water canvas and HUD share a CSS clip at the wipe percentage. Both sides draw the same decoded image with the same aspect-preserving viewport crop. Controls are a fixed scrollable panel, with mobile sizing, a 44-pixel toggle, visible keyboard focus, Escape dismissal and a native range alternative to pointer dragging. The control button maintains aria-expanded; status and percentage text describe current state.

The demo supplies small GameStore, Log and GfxQuality adapters. Its scene function decodes a selected original, rejects stale requests, then derives rain/storm from the scene name, clears droplets, resizes and advances a settled starting water state. A failed load preserves the previous image. configure forwards option setters; advance runs fixed 1/60-second water ticks. The animate property owns requestAnimationFrame cancellation and restart, caps elapsed ticks at 0.1 seconds and avoids ticking while a scene loads. Motion starts from the operating-system preference and follows preference changes until the checkbox explicitly overrides it. Airflow converts km/h to m/s. Choice controls derive from the runtime option catalog; the beams slider maps 0–200 percent through the option API. These are text-observed demo references, not a runtime or LSP validation of the underlying game modules.

The adapter expects runtime aliases supplied by visor-lab-export.mjs. That exporter copies the current game option, droplet and helmet stylesheet sources into an existing Site directory. It also copies authoring pages and image directories and merges captured pairs by ID, preserving destination-only pairs. Its exact source/destination relationships and the authoring-directory absence of aliases are in the evidence JSON. Exporting and publication were not run.

## Drive-by and binary assets

Each complete drive-by JSON has scene track/time/weather/camera/lap fraction, the same clear/medium-reflections/light-refraction settings, and eight ordinal frames. Each frame records speedKph, heading, track distance, projected sun or null, rays, projected glints with strength/beam/star flags, and paintMs. Bahrain accelerates to 124 km/h with up to four floodlight glints; Monaco reaches 112 km/h with changing tunnel glints; Spa reaches 151 km/h as the projected sun moves into view and rays become true on the final frame. These are stored observations, not measurements performed during mapping.

The three same-stem contact strips are RGB WebP, 1694 × 1682, one frame each; the eight originals are RGB WebP, 1920 × 1080, one frame each. Exact dimensions, sizes, hashes, metadata, per-image catalog provenance and source references are preserved in the evidence JSON. No direct drive-by strip consumer was found in the inspected lab text or shot-tool reference search. Numbered PNG names in the telemetry are historical supporting references; their exact paths and existence results remain solely in JSON. No image-specific license statement was found in the inspected lab sources or embedded metadata; provenance is not a license grant.
