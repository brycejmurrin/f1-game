## Composite actions

`.github/actions/setup-apex/action.yml` installs Node22 with npm cache and runs `npm ci`. It exports no named outputs and installs no browser binary. Its consumers include CI, browser-group, capture-gallery, car-shot and other native capture/deploy workflows.

`.github/actions/playwright-chromium/action.yml` accepts browser-directory and with-deps inputs and exports `cache-hit`. Cache identity includes runner OS, package-lock hash and actual runner image ID/version. Only a cache miss runs Chromium installation; with-deps defaults true and can be disabled for macOS. CI/browser-group and other browser jobs consume it; tests pin its cache contract.

`.github/actions/mesa-xvfb/action.yml` has no declared inputs or outputs. It retries bounded apt setup within a shared300-second budget, installs Mesa/Xvfb, launches display99, waits up to5 seconds for its Unix socket and writes `DISPLAY=:99` to `GITHUB_ENV`. Calling jobs choose whether to invoke it and set APEX_GL separately. Failure is explicit if packages or display readiness fail. There is no explicit teardown step; the display process lives for the runner job.

## CI prefix and its gates

CI has no push trigger. It runs on deploy-base PR opened/synchronize/reopened/ready/labeled/edited, daily04:17UTC, manual group/renderer/GL dispatch, or reusable calls from Pages. Reusable inputs are before_sha, concurrency_key and fast_tier_run. Default permission is contents read; selected jobs additionally request actions read. PR concurrency keys on head branch and cancels superseded runs; irrelevant labels/edits get unique noise groups, schedules/dispatches unique run IDs, and Pages supplies unique caller key.

Drafts opt into the fast tier with `run-ci` or a body line starting `CI: run`. Only the edit introducing that marker on an unlabelled draft starts work; ordinary Plan/body/title edits and irrelevant labels are ignored and named accordingly. An ordinary unopted draft gets a skip-notice job. Ready PRs use the full relevant tier. Header timing/history claims are explanatory provenance; operative conditions below take precedence over older comments.
