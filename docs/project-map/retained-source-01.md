The current generator's text establishes its two-leg design: parity compares the façade's member and writable sets against the type declaration and module factory roster; scope-aware extraction then follows module-context aliases and nested element aliases into the shadow. It takes candidates from manifest rosters, excludes circuit/scenery data, and filters factories that really take the shared context. Dynamic property access, whole-context forwarding and member-expression stashes are outside that extraction contract. The never sentinel deliberately erases assignment-value typing. Source locations live in an in-memory generated-line map used to rewrite diagnostics; the retained shadow itself does not carry a file/line annotation on every statement, despite its header's shorthand description.

Generated and historical names were not used as current runtime LSP definitions. No current runtime symbol relationship is claimed from these projections. Generator provenance was inspected as source text; no generation or TypeScript run occurred.

## Effects, evidence boundaries and cleanup

The shell selector would fetch before some later refusal checks, so refusal can still leave an updated remote-tracking ref. Its later mutations switch/create a branch and fast-forward; its guards avoid stash/reset or discarding dirty and nonancestor work. The installation payload would additionally install dependencies, build packages and mutate active plugin registration/cache. The startup payload would register packages and start/reuse the lifecycle owner. The fixture test would create local repositories, configure test author/hooks/signing and make commits in temporary directories. None of those actions was run during this map.

The dated reports describe GLSL compilation of 33 variants and explicitly skipped static WGSL/TLX coverage. Those are historical claims, not shader-source review or renewed compilation evidence; actual retained shader source is assigned to other groups. Local MCP catalog/status and doctor assertions remain distinct from hosted transport/account attachment, physical GPU behavior, gameplay coverage, CI and environment publication. Conflicting-looking statuses in the PR bodies represent successive snapshots, not a synthesized current verdict.

Cleanup candidates are the regenerable type projection, one of the identical PR-body copies, duplicate accessibility captures, and duplicated selector text once durable provenance and the meaningful historical state transitions are retained. Audit/repair reports can be condensed after their revision, dependency and capability boundaries are preserved. No deletion is recommended solely from a duplicate hash: capture chronology and downstream references may still matter. Supporting source paths and historical/missing paths are kept in the JSON ledger, with numbered IDs used here.

No tests, browser work, network access, installation, environment changes, source changes, staging or commits were performed. Only this map and its evidence ledger were written.
