## Release and landing contracts

`land.yml` evaluates PR label/unlabel, ready, synchronize and reopen events into the deploy branch, plus completed external check suites and completed CI/Pages workflows. The latter paths only re-evaluate successful runs. Its empty workflow permissions are expanded per job: resolve reads PRs; gate reads contents/PRs/actions and writes checks; arm/disarm write contents and PRs. Concurrency replaces an older evaluation for the same PR or triggering head.

The resolve job emits `landable`, a JSON `prs` array of number/head pairs, and `disarm`. It fetches current PR state rather than trusting the minimal completion payload; train completion lists up to 50 open `land` PRs. Eligibility is open, correct base, ready, `land`, and no `hold`. Already armed open PRs failing eligibility are disarmed. Gate checks out the trusted deploy branch with full history and invokes `tools/ci/merge-gate.mjs --pr --sha --check` for each candidate. Its documented subprocess boundary strips credentials and GitHub output paths from merge-result scripts. The command's exit determines verdict and successful heads enter the `passed` output. PR events use the job's check; completion events explicitly create a `gate` check on each PR head. Refusals fail the PR-event job; off-PR failures are represented by those posted checks. Arm uses head-pinned GitHub auto-merge with merge commits, preferring `LAND_TOKEN`; the GitHub-token fallback warns that it cannot trigger a Pages push train. Disarm disables auto-merge after eligibility is withdrawn. Repository auto-merge and required-check configuration remain external assumptions.

`pages.yml` starts on deploy-branch code pushes, six-hourly cron at minute 41, or dispatch. Its prose/agent configuration ignore patterns defer those pushes to cron. The workflow lock `pages-train-${github.ref}` and gate lock do not cancel running work; deploy additionally locks the shared `pages` slot. Only deploy receives Pages/OIDC write permissions; other jobs declare narrow read permissions, except live verification's issue writer.

The dependency chain is `verdict → ci → publishable → deploy → verify-live`, with explicit conditions allowing the reusable CI call to be skipped only for an already-tested equal tree. Verdict refuses other branches, reads the live shell SHA, emits `nothing_new` and ancestor `since`, then asks `tools/ci/pages-reuse-verdict.sh` for `reuse/source/run`. Unknown live history selects a full gate. The reusable `ci.yml` receives that live ancestor as `before_sha` and a unique run concurrency key. Publishable admits only successful gate or successful reuse and consults `tools/ci/pages-publishable.sh`; deploy repeats the monotonic ancestry check with `--strict` under the Pages lock. This preserves the checked-out `GITHUB_SHA` throughout staging and publication.

Deploy stages runtime files with `tools/desktop/stage.mjs`, stamps build/provenance, asserts the staged apex-sha meta, and uploads a run-attempt-specific Pages artifact. Outputs are build and page URL. Live verification recreates the stamped tree, polls for matching build/SHA or a superseding descendant, and compares runtime bytes/lazy assets only on exact match. Failure opens an issue carrying build, SHA and run. `tools/ci/ci-watch.mjs`, base-verdict/base-green tooling, the dispatcher and reuse tooling consume Pages results; `tests/unit/deploy-staging.test.mjs` pins shared staging. The live-failure issue body still says four minutes despite the workflow's 15-minute job cap and delegated backoff: treat this text as a cleanup candidate, not the polling contract.

## Data-producing maintenance

`import-models.yml` is dispatch-only with URL required plus material, height, scale, prefix, author and destination branch. Contents write and persisted checkout credentials support publishing. Non-cancelling concurrency keys the destination branch across source refs. The downloader requires HTTPS, logs origin/path without signed query, detects ZIP/glTF formats, rejects absolute/traversing/symlink ZIP entries, then calls `tools/gen/import-models.mjs`. Credits/asset verification failures are explicitly advisory; upload includes baked models, manifest and credits. The branch guard rejects deploy/invalid destinations; an existing destination must have a bot-authored tip and receives an exact-tip lease. It stages only model pack outputs, checks shell generation, and pushes a bot proposal; importing does not itself place models in circuits. The artifact uses the platform default retention, with no explicit override.

`process-dashboard.yml` runs daily at 04:47 UTC or dispatch, non-cancelling singleton, with contents write/actions read. It reduces the latest 60 runs using `tools/ci/process-dashboard.mjs --baseline`, writes JSON/Markdown to temporary files and the summary, and checks time ratchets as advisory. It then switches to or creates the metrics branch and commits only the two records. The tool is called before checkout replaces its imports. Readers fetch the metrics branch; no deploy-branch mutation occurs. The workflow still describes cancelled Pages runs as superseded in supporting tooling text, but the current train does not cancel running publishes.

`ratchets-fold.yml` runs daily 06:17 UTC or dispatch with numeric minimum fragments default 20. Its non-cancelling singleton has contents/PR/issues/actions write. Existing open fold PR means no fold. Otherwise `tools/check/ratchets.mjs --fold` consolidates already-landed fragments; no changed test data means clean exit. The ratchet check and regeneration gate the bot commit, followed by a leased bot-branch push and PR creation. CI is explicitly dispatched on that head because a GitHub-token PR does not reliably initiate PR CI. Refused PR creation still attempts CI, then creates/comments on one handoff issue and fails; dispatch failure itself only warns. No auto-land label or landing plan is added here.

`spec-timings.yml` consumes every completed deploy-branch Pages run, including failed trains, or manual dispatch. It stays separate from the read-only reusable CI gate because its token writes contents and reads actions. A non-cancelling singleton accumulates the previous bot-side record before downloading `spec-timings-junit-*`. Dispatch selects the newest successful standalone CI run instead. Missing junit is a normal no-op. Found files are merged under the llvmpipe CI environment bucket; checks and step-regression summaries are advisory. Only changed timing data is committed; bot ownership and deploy-branch refusal bound an intentional force-push with repository hooks disabled. Current CI selection reads this side branch through `APEX_SPEC_TIMINGS` in `tools/ci/ci-select-specs-step.sh`; a hand merge is not required for the planner overlay. Its introductory explanation still mentions an older Pages caller permission set: the current Pages call grants actions read.
