## Load and renderer ownership

`tools/manifest.cjs:140–156` places the shared device facade, budgets, common helpers, mesh parser, assets, driving line and puddle reference before backend consumers. Compatibility recovery is later (`:389`); shadow and mirror orchestration are near game entry (`:474–475`). Generated script tags agree at `index.html:3667–3685`, `:3883`, `:3960–3961`. The explicit evaluation edges include M4 before DrivingLine/Puddles (`tools/manifest.cjs:695–696`), LightBudget before LampChunks (`:765`), and MirrorPass before game (`:857`). LampChunks reads Frustum at call time, so its earlier evaluation is intentional.

`glx-facade.js:5–26` creates the stable `GLX` object or reuses `window.GLX`. It determines the mobile tier from forced storage, UA and Mac multitouch before any context exists. `install(backend)` copies property descriptors so live getters and object identity survive binding.

`gfx.js:239–256` supplies revocable canvas ownership: the Proxy refuses later `getContext` and property writes after abort, exposes the real canvas as `__element` for ResizeObserver, and records successful context claims. `create` (`:267–312`) chooses the supplied backend override or saved preference; unset means THREE. TLX has no `navigator.gpu` prerequisite because three can fall back internally. Other preferences require navigator.gpu; explicit WebGL2 returns null, otherwise WGX is attempted. All refusal/exception paths return null. A revoked owner discards a late backend through best-effort dispose/destroy (`:260–265`). This factory does not bind GLX itself.

`RendererBoot.create` owns the actual boot decision and error recovery. `game.js:110–116` constructs it, awaits `start`, stops on null and adopts the returned renderer. Preference resolution (`renderer-boot.js:45–60`) honors resident XR advice, normalizes invalid saved picks to WebGL2, and otherwise defaults to THREE. An unset THREE default probes an adapter before downloading THREE; explicit THREE remains allowed without a successful probe. Adapter probes cap at 4 seconds (`:74–105`); a slow WGX adapter remains eligible for its own backend initialization.

`renderer-boot.js:118–184` has distinct waits: adapter cap, ordinary backend-init timeout (15 seconds, storage may raise to 60), and script progress idle timeout with a separate 60-second wall maximum (raisable to 120). Script settlement touches the idle timer. Timeout cannot cancel browser promises, so alternate initialization uses the Gfx owner to revoke access. A backend that has already claimed a canvas prevents same-load GLX attachment (`:355–357`). Failed GLX init may reload once with a session skip, but only if the latch can be read back; a second failed recovery shows graphics unavailable (`:376–403`). Missing scripts and fetch timeouts do not enter the reload loop.

The boot canary is per backend (`:245–275`): first unfinished prior boot falls back for this load, second consecutive strike retires the pick. Descriptor-copy bind (`:336–346`) preserves GLX identity and announces `apex-gfx-live`. GLX fallback publishes actual binding and reason to session storage (`:404–424`). `proved()` only clears strikes after an alternate actually bound (`:438–441`); fallback GLX cannot prove a failed alternate. `guess/preloadLikelyBackend/kickEarlyAdapter` (`:462–530`) do run during module evaluation: they fetch likely roster bytes without evaluating them, avoid speculative unset THREE bandwidth, and share a single early adapter promise with start. THREE vendor modulepreloads wait until the committed THREE path (`:11–31`, `:307`).

## Pass orchestration

`ShadowPass.create(G,deps)` captures the live LightTune.LT object and owns light matrices, caster pools and cached content keys. `game.js:3548` injects team silhouette, speed normalization and cockpit caster. Returned `livePlayerMat` is writable producer scratch; `beginFrame/pushCaster/flushBlobs` collect current grounded transforms while sun/lamp passes consume the previous field pool plus live player. `reset` clears track references and invalidates old car-map keep eligibility (`shadow-pass.js:172–195`).

The sun pass (`:243–498`) derives a light basis, adaptive near-side depth span from prop height, and snaps right/up coordinates at range/4. Shadow anchor is camera-based but forward bias follows player heading, avoiding camera-yaw strength changes. Gate depends on actual key brightness/moon floor; closing it invalidates snap keys. Static rebuild casts terrain/road, chunked props and light-frustum-culled instances; lazy ribbon chunking respects governor tier and backend track-coordinate capability. Dynamic car-map uses current player and prior AI transforms, a separate ±42 m scaled box, exact horizontal corner bound plus car margin, skips empty passes, and keeps cadence-skipped valid maps armed. Phone capability, knob, tier, state and actual lighting gates precede expensive caster resolution.

The lamp pass (`:513–715`) excludes tail records by range and small movers by radius, chooses distance²/luminance with a 1.2 handover hysteresis, and keys map content by lamp position/radius/cone/direction plus quantized caster matrices. Same content keeps the map armed with THIS frame's lamp index; only car changes may defer one odd frame at tier>=1. Player and rivals share lamp radius+8 bound. TLX can reuse static prop depth via lampStaticBegin/lampCarsBegin; absent/refused hooks fall back to complete pass. Instance shadows use a separate shadow pack (`upload:false`) so camera buffers are preserved.

`MirrorPass.create(G,deps)` is constructed at `game.js:3550–3552`; world draw, mirror car draw, pose helpers and paint are injected. It owns one backend target shared exclusively by rear-view and broadcast PiP. Mirror modes, session-only collapse chip, camera eligibility, software AUTO and XR gates are in `mirror-pass.js:233–300`. PiP uses its own subject/setting and unflipped minimum rung. Rects are CSS-measured canvas fractions at 500 ms, invalidated immediately by rotation/resize; radio-card side placement also excludes touch docks (`:302–370`). Target sizing is CSS×capped DPR×rung resolution×2 supersampling, aspect-preserving clamp 1024×512, following main scale down to lite floor (`:205–232`).

Quality selects full/lite/low/min; phones follow measured auto tier with lite floor and explicit LOW honored, desktop follows total tier (`:579–590`). Rungs hold 90 render invocations. Current actual lite/low/min hard cull is 120 m; cadence every 1/2/3. Full instances reuse last mirror pack at default every other successful consecutive full pass, resetting after interruptions (`:711–745`).

Preparation (`:475–570`) is driven by render during countdown, waits for queued renderer warm before real-size pass, has a 30-second bound, and only reports prepared after backend render counter/ready checks. Diagnostic counters separate warm, missing frames and refused pass causes. A pass swaps camera/frame/sky/light/tune fields, suppresses sun glints and shadow strength through a prototype tune view, reranks mirror lamps with short cache, draws world/cars/sky, calls mirrorEnd, and restores fields in nested finally (`:688–761`). This must precede main begin so post matrices describe main view. `standDown` clears composite/UI outside render; releaseTrack drops lamp-cache track references. `drawing()` means image available for cockpit glass, including cadence-held texture, not necessarily a new render this invocation.

## Proven comment mismatches (source unchanged)

1. `gfx.js:15–20` and `:271–272` disagree about orchestration home: header says game injects/decides fallback; code's real caller is RendererBoot (`renderer-boot.js:312–424`, game:110). Header's `:174` names LightTune.TUNE_DEFS while common knob lookup reads LightKnobs.TUNE_DEFS (`post-common.js:163`). These are ownership/registry documentation mismatches.
2. Assets `:789–790` says all model data arrays are Float32Arrays; actual indices are Uint32Array in v1 (`:817`) and Uint16Array in v2/v3 (`:826`). Vertex channels are Float32; indices are not.
3. Assets `:958–959` says a hanging readiness fetch resolves 0 at timeout; `modelsReady :968` resolves -1. A no-source fast path and failures use 0, timeout is distinguishable.
4. GLTF `:350` says missing normals compute flat face normals; actual `:424–426` and `:446–479` accumulate unit face normals at shared vertices then normalize, producing smooth averaged normals.
5. LampChunks `:95–100` describes buildTable's old hits/Math.min prefix algorithm; actual `:36–80` uses a bounded heap. Prefix semantics remain, implementation explanation is stale. Its `:106–108` ownership comment says avoiding shared buffer protects master copy, but unchanged-length list explicitly reuses src; only truncated lists are copied. Consumers must treat unchanged lists as borrowed.
6. Mirror quality commentary `:43–47` promises 180 m cull/140 m rivals on lite; actual LITE_CULL=120 (`:78`) and QUALITY (`:85`) cap both at 120. Later commentary `:79–82` explains the newer distance.
7. Mirror target commentary `:137–139` says render-buffer rescaling avoided target reallocation; `:205–231` explicitly includes main render scale and reallocation. CSS measurement still decouples raw buffer dimensions, but scale does participate.
8. Shadow lamp key comment `:604–607` calls orientation quantization 1/8 rad; `_lampCasterKey :509–511` quantizes forward-vector components in increments of 1/8, not angle. The earlier comment at `:500–502` is accurate.
9. Shadow lamp comment `:517` hardcodes other 31 lamps; live slot maximum is 48, mobile 24, lite 16 (`light-budget.js:13–18`). Actual lamp loop reads frame length (`shadow-pass.js:528`), not a fixed 32 slots.

## Limits and verification

This map establishes source/control/data flow, not visual correctness, GPU availability, measured timing, exception reachability or complete dynamic caller coverage. Backend source outside this scope was reached through LSP references and narrow call-site excerpts, not fully reread. Shader math parity was not rerun; Puddles is intentionally hand-mirrored. GfxRecovery creates a live instance and attaches UI only on matching failures; backend state/vendor stack gate is exact (`compatibility-recovery.js:9–16`), and no direct external JS consumer was proven by the module query. Browser, software-renderer and device behavior remain unverified.

Verification for this documentation is the parent's combined docs-only integrity/config check after all map edits. Hash ledger and file count were generated from the examined source; no source/browser/test mutation was made here.
