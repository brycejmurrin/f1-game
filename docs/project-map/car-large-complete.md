## Car3D

`Car3D` is the procedural facade: `build(color,color2,opts)` emits plain indexed geometry (`pos/nrm/col/mat/idx`) and `flapInfo`; `buildComplete` appends movable flap geometry in its design pose (only reverses pivot translation, deliberately applies no solved rest rotation). Local axes are +Z forward, +Y up; origin is ground under cockpit. The fixed axle datums are front Z 1.7, rear Z -1.6, wheel Y .34 (line 13).

Construction owns shared palette/geometry/body/wheel factories, style catalogs and livery appearance overrides (1–236); chassis, cockpit-specific hood/bolsters, sidepods, floor rails and engine cover (237–1000); detailed floor/body paint/SDuct, nose decals' substrate, running lights, cockpit halo (1001–1400); exterior halo accessories, mirrors, driver/helmet and exhaust recipes (1401–1900); fin/vents/front cascade and rear assembly (1901–2400); rain lamp, diffuser/gearbox/brakes/suspension/wheels and finish/measurement/weld pipeline (2401–2865); complete-build and facade exports (2867–2899).

`bodyStyleKey(teamId,bodyStyle)` accepts saved team swaps even though picker-facing `ALLOW_TEAM_BODY_SWAP=false`; known body style wins, otherwise team style, otherwise default. `appearanceParts` clones fitted tiers and `_visual/_ids` only when a valid STYLE option overrides geometry: ownership/performance remains in fitted parts. All geometry consumers must resolve through this recipe. Pale cockpit accent paints use `_ckAcc` (minimum channel >= .45 scaled to .42); primary body paint stays exempt.

`opts` branches include cockpit, noWheels, ownHalo, noDriver, silhouette, field, parts/livery/teamId/num/helmetKey, cockpitBody/halo/cockpitHalo, smooth, measure, refinish, shadeKeep and noWeld. `shadeFlags.round/coverHi` are shared mutable factory context, set for one synchronous build and reset before finishing. `measure` keeps vertex ranges/part bounds; `refinish` snapshots material/color/normal streams plus reusable smoothing geometry. Normal default builds weld unless opts forbids it. Silhouette outputs request TLX CPU mirror release.

## CarBodyGeom

Factory dependency contract: palette/material IDs, axle/chassis/default/team/body datums, `teamStyleOf`, geometry primitives and shared `shadeFlags` (17–26). Public global exposes only `create` and `chineCut`; factory returns the body-builder and anchor contract consumed by Car3D (2168–2184). LSP: five module references in three files: own declaration/freeze (2), `car-shade` (2), `car3d` (1).

Complete sections: styled/concept/curved noses, closed-skin helper, halo path and wing envelope/profile (1–400); collision-sampled front hinge solve and rigid rear flap solve, per-style/signature memo, movable mesh and sponsor-band placement (401–850); fin shapes/root/panel/badge and cover profile, mirror anchors, default part recipes and chassis start (851–1300); cockpit aperture, pod station interpolation/clamps/detail fitting and authored concept pod profiles/cap triangulation (1301–1750); concept pod emission, memoized anchors, sculpted pods/roof/inlets/exits and cover lofts (1751–2184).

`bodyAnchors(parts,teamId,spineHeight,round)` caches by parts identity and style/spine/round key; returned samples (`podAt`, `coverAt`, `noseAt`, `podFlank`, `podSeatY`, roof/ring/stops) are the shared geometry/decal/detail source. Callers must replace mutable parts identity when geometry changes. `coverProfile/coverFlankX/coverSurfaceY` keep details on rendered cross sections; `COVER_STACK` orders vent (.005), shield (.008), decal (.013), flank trim (.009), flank decal (.014).

`aeroFlapsGeom(level,recipeObject)` returns shared immutable records, memoized by weak style identity then normalized signature. Front solve searches hinge and end poses with nose gap .005 and cascade gap .003; rear stack shares a single .72 pivot and incidence endpoints .56/.035 radians, preserving rigid internal slots. `buildFlapGeom` emits hinge-relative geometry, carbon or finish-correct paint and welds. `wingBandGeom` samples the topmost rear flap at solved CLOSED pose; it is a static decal, so it does not follow animation. `frontBakedCount` preserves static main plane and leaves up to two upper elements movable.

Pod station validity clamps protect minimum widths/heights, top <= .65 and belly/undercut envelopes. Concept noses pin tub seam and lift free stations to clear worst team-nose floor. `fitBodyDetails` is opt-in and seats floor/nose mount/cover stripe/TVane from anchors. Complete sculpt/curved/concept paths are distinct from legacy linear lofts and share sample stations with their decal consumers.

* `car-body-geom.js` comment above `frontBakedCount` says “How many of them the mesh still bakes. Never the main plane.” The implementation returns cascade count minus up to two upper movable elements, hence always DOES bake the main plane. The following frontCascade main-plane comment and Car3D loop establish the intended meaning: main plane never moves.

* `car-mesh.js:1881` describes the baked rain LED face as z -2.60 at y .50. Current `car3d.js:2405–2412` sets lampY .545 and glowing faces centered at -2.590 and -2.5935 (rear extent -2.595). ## CarMesh

Full coverage: decal-data/anchor/UV emission and key front (1–400); decal cache, cockpit decal, brake/spin/compound/crew meshes, effect quads and flap caches/sets (401–850); rig primitives, seven wheel designs, finish remapping, wheel roll and forearm geometry (851–1300); arm transforms, column/dash, all cabin trims and classic gauges, mirror fallback/live mesh, LEDs and digits (1301–1750); ERS/aero/OT/status telemetry, rear lights, debug aero edges, queued road-tail glow and mirror lamps (1751–2105).

`init(gfx)` establishes the renderer handle required by lazy getters. Geometry contracts split opaque colored material meshes (`pos/nrm/col[/mat]/idx`) from textured decal/mirror meshes (`pos/nrm/uv/idx`). Decal UVs compensate the reflected car basis (U preflip) and atlas V orientation. Procedural decals use the same Car3D body/cover/fin/flap/plate anchors as physical geometry; imported GLBs deliberately use default anchor parts. Normalized recipe JSON, anchor key, halo/fin/body shape and round state join decal cache identity. Identity memoization assumes resolved parts/liveries are replaced on edits. Cockpit number decal is a single four-corner quad, unlike exterior noseStops strip.

Caches are deliberately mixed: decal meshes FIFO cap 24; flap elements FIFO 128, flap sets FIFO 64, paint-key maps per shared record; crew color FIFO 32; wheel/cabin singleton replacements free previous GPU meshes. `releaseIdleFlaps(ms)` measures idle relative to newest flap draw (not wall clock), frees mesh/set buffers via `freeMesh`, clears memo rows when sets disappear. Effect/digit/compound/mirror caches lazily retain their finite or caller-controlled key space. `getAeroFlapSet` rotates hinge-relative geometry into solved rest/open pose; `getAeroFlap` leaves transformation to caller. Finish and rearWing color participate in keys.

Wheel helpers expose seven styles and per-surface finish choices, progressive steering `-(.8*s+.7*s^3)` (lambda 12), optional forearm geometry, classic/retro/modern telemetry and live mirror UV sampling. Main CarDraw currently deliberately does not submit forearm sleeves (user-directed comment). `ersLightCode` returns 1/0 for deploy/clipping flashes, -1 for no override. `drawTailGlow` uses a sampled road slope and queues matrices only on decalRuns backend; caller must flush after car loop. Rear-light mesh is pinned when backend supports it.

LSP: 58 exports/149 internal; module consumer references: 59 across CarDraw (20), cockpit-preview (15), game (12), setup-camera (5), agent/apex (4), perf/bench-run (1), own (2). Full public getters/draw helpers/constants appear at 2101–2103.

## CarDraw

`create(G,deps)` is the game facade seam and single runtime instance. `G` supplies renderer/store/cars/player/view/session/track/parts access; deps supplies resolveLivery, partsVisualKey, drawAeroFlaps, damp and mode predicates. Main game owns per-frame car loop, ground/attitude matrices and shadow passes. Module global exports create/carVisual/instance/coOpt; instance exports named body/wheel/decal/warm/FX/mirror/invalidation methods and read-only modelBuf/playerVisualKey/menuCarAssets getters (2150–2174).

Full sections: bounded cache helpers, factory/player keys, optional imported model, mirror experimental simplification, shared far body and atlas cache front (1–400); atlas eviction/draft reuse/photo plan/deferred bitmap hi-res/atlas resolution and recipe-state cache (401–850); race/menu warm scheduling/cancellation/phase gates and decal submission (851–1300); decal queue/cockpit caster/rig/mirror glass and telemetry, player and field wheel caches (1301–1750); shared wheel phases/planting/LOD/rings, mirror car, exhaust FX, model loading/invalidation/instance exports (1751–2174).

`carVisual` gives factory-equivalent setups factory keys; nonfactory career shelves get setup/id stamps, painted suffix includes driver number and shadow suffix shares between seats. Team mesh/body caches LRU 40 each; player/cockpit bodies 3 each; player wheel combinations 8, field 12. Shared far body target 1500 triangles is prepared with epoch checks. Experimental mirror body clusters exact material/color cells .06 m, preserves indexed extrema, and only warms via covered opt-in policy.

Atlas LRU cap is 36 slots and 160 MiB estimated RGBA+mips. Player preview is immediate; desktop hi-res async upgrade captures livery/key/team-pick ownership and rechecks after await; old preview waits until next bind/flush before freeing. Bitmap orientation differs by backend (GLX flip baked, three/WGX unflipped); source ownership transfers only to three. Draft textures can refill two spare handles; photo rivals get one preview mint/frame, maximum six, no full-res schedule, released on leaving photo. Sync failures retry three times then cache null; hi-res retries two. Stale sweeps preserve current field keys even when decals are culled.

Warm sync/async/menu paths share actual cache keys and four phases (body, atlas, caster, launch LOD); async yields between expensive steps, caller keeps cover up, predicate cancellation stops future work. Optional rear-grid atlas/casters drain during countdown. `advanceWheelPhases(dt)` runs once per render frame before mirror: mirrors/main/cockpit read identical phases, human wheels derive input+speed taper while AI includes curvature. `drawPlayerWheels` separates rotating and fixed layers, compound/ring/blur gates and pit jack/removal pose; bare mirror submits rotating wheels only. Decals copy model matrices into a pooled queue and flush after opaque bodies. Cockpit shadow uses whole exterior silhouette with own halo/no driver and viewmodel-aligned axes.

## LiveryTex

Full sections: atlas tier/device policy and all pixel regions, sponsor/font catalogs, linear-light contrast, text/number painters (1–400); clipping/mark palette/brand/legend identity and traced crest factory (401–850); custom emblem generation/decode/size guard, mark rows/image/crest drawing, wrap sun/bull and contrast derivation (851–1300); flank frames/geometry compensation, cover/fin binding and fill-gating, mark bounds, canvas source and atlas initialization (1301–1750); crown/logo/wrap/design/fin/side layout and first side painters (1751–2200); remaining side painters, board sponsors, station/number lockup, shared mark painter and swatch/card caches plus exports (2201–2676).

`buildAtlas(teamId,colors={},numberOverride,isPlayer,hiRes)` returns HTMLCanvasElement, never OffscreenCanvas. Authored coordinates are 2048×2560; REGIONS are pixel-space and consumers divide U by SIZE, V by SIZE_H. Actual preview/AI/mobile canvases paint at upload dimensions through 1/div context transform, avoiding a full-size intermediate. Mobile player divisor 4 / AI 8; desktop preview player 2 / AI 4; hi-res desktop player 1. Player device-tier differs from AI device policy (`atlasMobile`): high graphics phone player gets preview 1024 while AI remains phone-safe 256. CarDraw separately forbids phone hi-res upgrades. Mobile scratch canvas is reused: caller must consume/copy synchronously before another atlas overwrites it.

`colors` is copied and migratePaint applies before painting. Primary/secondary defaults, per-surface colors and design picks feed palette/text/number derivation; explicit authored choices are preserved, derived defaults seek contrast. `contrast` linearizes sRGB; `inkOn` returns copied RGB array tagged `.worst`. `markBase`, `markOnField`, `markPalette` resolve requested/team brand/derived roles (mark, alt, plate, part, outline, halo and actual under surfaces). Legend IDs resolve marque for crest identity while tribute paint stays separate. An authored/brand free mark has no automatic substitution or auto-halo; this intentionally limits universal contrast guarantees.

`setTeamLogo(id,src)` has per-id generation tokens, refuses >1 megapixel decode, clears stale emblem on error/clear and notifies all listeners independently. Uploaded marks route logo tint plus logo3 outline; no second-shape color. `markSlots` adapts editor rows to actual mark geometry/upload. Mark-change callbacks clear swatch/card caches and external callers invalidate their textures. `paintTeamMark` is the shared atlas/tile/flank renderer; swatch paint cache FIFO caps 160, adopted card canvases also cap 160 and use build stamp to avoid moving same DOM node twice in one build. Fonts must be loaded before caching.

Cover/flank visual contract: explicit FLANK coordinate frames mirror side-specific region direction, CROWN_SQUASH and FLANK_H compensate physical anisotropy, FLANK_SEEN bounds readable content before rear tyre. Crown fill → bull/design → lettering order prevents solid side panels erasing the identity or lettering. `FILL_SURFACES/fillInert` are the authority for editable rows that a design can spend. `sunColour/airboxMeshColour/resolveFinPaint` join atlas and physical mesh paint; Car3D calls them directly. LiveryGraphics and LiveryCrests are separate injected helper factories; LiveryDesign/LiveryStations optional globals extend both pattern IDs and painters.

Known boundary explicitly admitted by source (1788–1804): atlas lockup excludes fin only for `finShape:none`, whereas CarMesh also excludes a physically swallowed fin (`sharkFinRoot.clear <= .03`). Atlas receives no parts, so a non-none fin below tall crown can still influence a palette for texels nothing samples. This is a source-confirmed limitation, not newly reproduced behavior.
