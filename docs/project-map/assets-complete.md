## Evidence and limits

Every file has a whole-file SHA-256, byte count, type, and inspection result below. The 35 text files were consumed through EOF as bounded 8,192-byte chunks and UTF-8 decoded; all 25 JSON documents were parsed completely. All manifest records and every voice clip offset/length/duration were structurally traversed. Prose/licences, the material manifest (lines 1–1339), and webbake (lines 1–556) were also read as source in bounded terminal output; an initially truncated combined output was recovered with smaller reads. Voice manifests are single-line generated indexes totaling 1,031,532 bytes: their coverage claim is **complete machine parsing and validation**, not a claim that every repeated numeric tuple was manually read in conversation. The line column denotes physical source extent, not binary lines. No claim of visual or listening sign-off is made.

PNG/WebP headers and container validity were checked using Pillow (`verify`, no rendering). All 41 AX26 model headers, exact byte sizes, position finiteness, index bounds, declared vertex/triangle counts and manifest MD5s were checked; all are version 2. All four pack-strip MD5s agree with the manifest. Every voice binary agrees with its manifest SHA-256 and size; all indexed clip intervals fit, cover their whole binary with zero gaps, and do not overlap. `ffprobe` inspected every music/SFX/voice binary. A concatenation of independently encoded clips is not one continuous recording: whole-file ffprobe duration is advisory; the JSON rows carry the clip-duration sums.

WOFF2 headers were inspected (signature, flavor, file length, table count, uncompressed/compressed byte sizes, version). Installed FontTools lacks its Brotli extension, so glyph-level font decoding was unavailable; no dependency install was attempted. Existing `tools/check/font-digits.py` and `tests/data/font-digits.json` are the repository's deeper font audit route, not evidence of a new run here.
