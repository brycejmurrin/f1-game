## Architecture and data flow
- `tools/manifest.cjs` is the module/load-order authority according to root AGENTS and the generated tools index. The manifest body was not inspected here; consumers include VM harnesses and generators.
- Change routing starts with Git paths: fully read `tools/lib/changed-files.mjs` invokes `git diff --name-status -z -M`, preserves rename/copy source and destination, and deduplicates paths. `pick-tests.mjs` imports this helper and holds coarse path-to-group rules; its header recommends `select-specs.mjs` for finer per-spec selection.
- `tests/groups.json` is the test-group source. Fully read `tools/gen/gen-test-groups.mjs` builds browser commands through `run-playwright.mjs`, Node commands through `node --test`, and isolated Node groups through `run-node-group.mjs`. It rewrites/removes matching package scripts and supports a non-writing drift check.
- `tooling-fast.mjs:87` loads `filesOnly(loadGroups().toolingFast)` at import time. Its opening implementation separates suite logging from background-group logging and imports change selection, worktree identity, spec selection and topical Node planning. Scheduling/termination implementation beyond the opening was not audited.
- Browser tools share `tools/lib/harness.mjs`: its inspected opening imports Chromium resolution and HTTP/file-serving APIs, and describes ownership of server/browser teardown. `tools/lib/game-vm.cjs` instead uses Node `vm`, the module manifest, browser stubs and `__apex` stepping. VM results cannot establish rendered correctness.
- `tests/helpers/fixtures.js` exposes shared boot/build budgets and `clickLive`, with imports for Playwright, VM-backed fixtures, coverage and factory seat state. Its header describes preboot test pins, deterministic API mocks, console capture and log attachments; downstream implementation remains only partially read.
- Scope layers: `tests/unit` contains Node suites; `tests/specs` browser regressions; `tests/manual` deliberate human inspection; `tests/helpers` shared execution/fixtures; `tests/data` committed fixtures, impact pins, quarantine and timing evidence; `tests/vendor` pinned test-only runtime. These roles are supported by paths and selected documentation, not a complete file audit.
- Tool families visible in the inventory include generators, CI/run/deploy orchestration, MCP adapters, captures, track verification, UI audits, graphics/performance diagnostics, environment/bootstrap and asset/car/garage instruments. `tools/README.md` is generated from first-15-line header tags; its opening defines skill → CLI → pinned MCP layers and bounded agent output.
