## How Apex tests consume it

`tests/vendor/README.md` is the complete provenance and upgrade guide read for this map. This is pinned Meta IWER **2.5.0**, copied from npm's build output, and is test-only. Production `index.html` must never reference `tests/vendor/`. The guide identifies MIT IWER plus Apache-2.0 embedded dependencies; the read span itself contains the full Apache-2.0 webxr-layers-polyfill notice and MIT gl-matrix 3.4.3 notice. Preserve attribution on replacement; this map does not independently establish upstream package integrity beyond the checked-in hash and guide.

`tests/helpers/iwer-install.mjs` loads the UMD with `page.addInitScript({ path })`, then injects a serializable fixture before navigation. It sets TLX/forceGL/LOW fixture preferences, checks global XRDevice/metaQuest3 availability, constructs the profile, calls `installRuntime({ forceInstall: true })` and enables stereo by default. Force-install replaces headless Chromium's XR stub; stereo prevents a zero-width right viewport. It publishes `__iwerDevice` and `__iwerInstall` for assertions. The helper's exported launch arguments select ANGLE/SwiftShader and disable background throttling. XRDevice implementation and metaQuest3 profile definitions are outside this group's read range; their use is verified from the helper, not from an unread vendor tail.

For device version 2.5.0, the fixture wraps `XRReferenceSpace.prototype.getOffsetReferenceSpace` once, marked by `__apexMatrixAdapter`, forwarding `transform.matrix` to the vendor method. `wt` forwards the object unchanged, while `de` clones numeric indices; an XRRigidTransform object has a matrix property instead of those indices. The adaptation is restricted to the emulator fixture. The standard application API continues to receive an XRRigidTransform.

Production LSP definitions establish the consumer boundary: `XrSession.recenter` at `js/xr/xr-session.js:335` obtains the base-space viewer pose, asks `XrRig.recenterOffsetFromPose` for position plus yaw-only orientation, constructs XRRigidTransform and calls the standard offset API. The rig function is at `js/xr/xr-rig.js:199`; pitch/roll remain available after centering. `XrSession.eyeFrames` at `js/xr/xr-session.js:371` queries the current reference space, inverts each eye pose and composes the anchor/projection and layer viewport. LSP returned the recenter body via module-file fallback and explicitly did not establish complete callers/export coverage; eyeFrames and the rig function included export rows.

`waitXrReady` waits for XrBoot binding as well as XrSession: without a base layer the vendor session loop produces no application frames. `waitXrFrames` uses a single page evaluation, a settling interval and Node watchdog, reading the game's frame counter instead of registering a competing XR callback. `sampleXrEye` deliberately samples within the callback that owns an active frame. `waitWhilePresenting` is intended for signals after session exit; canvas capture uses requestAnimationFrame plus toDataURL.

## Verification boundaries and maintenance

- `tests/unit/xr-phase0.test.mjs:198` pins vendor presence and the production-shell exclusion. Its actual-vendor regression at line 810 executes real space/transform/frame classes in a VM **when the test is run**, stubbing only device installation. It first asserts the original NaN defect, installs the fixture twice, then checks finite offsets, viewer/stereo midpoint centering, 0.064 m IPD and negative nested-offset sign. Reading this test is not a passing result; it was not run for this map.
- `tests/specs/vr-emulated.spec.js` installs stereo IWER before each test and constrains software rendering to LOW/half resolution. Titles and selected source establish lifecycle re-entry, seated pose/movement/recenter, controller input, disconnect/visibility, backend fallback, exit restoration, reload and stereo canvas boundaries. Only its first 160 lines and targeted title/reference searches were read here, so later assertion details are not claimed fully reviewed.
- `tests/specs/xr-plan.spec.js` was fully read: webgl2 boot path and armed WebGPU fallback when XRGPUBinding is missing. It records the software context's xrCompatible report rather than treating it as real headset proof. `tests/unit/ci-gate-selection.test.mjs` has fixture/vendor path filter assertions; only matching references were inspected.
- Software emulation does not qualify Quest GPU frame times, foveation effect, multiview, MSAA or XRGPUBinding. Optional anchors, hand recording, depth, SEM and composition-layer machinery in this span are dependency capabilities; no direct Apex consumer was established for those facilities.

Cleanup candidates are upgrade work, not deletion recommendations: recheck/remove the version-gated offset adapter only when the actual-vendor regression proves the upstream contract is corrected; evaluate unused pose/layers bulk only through an upstream replacement/rebuild with full dependency and license review. Do not surgically edit the minified bundle. Upgrade the npm dependency, re-copy/rename the build, update the helper and pinned canary together. New support artifacts for this map are `tests-vendor-01.md` and `tests-vendor-01-evidence.json`; no historical/obsolete paths were introduced.
