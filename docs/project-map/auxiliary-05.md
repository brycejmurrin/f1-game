## Capture CLI contracts

capture.mjs is a Node ESM Playwright-library driver with positional mode and optional output directory; the default runs the spike then GLX baseline sequentially. It starts a loopback static server, normalizes decoded request paths and requires the repository root plus a separator. It serves files with MIME, content length and no-store. Each browser closes in finally and the server closes even if capture throws.

The spike arm loads its standalone page with forced WebGL2, wraps four WebGL draw entry points, captures four orbit angles at 960×540 and compares 32 lamps, 8 lamps and instanced cars. Its timing samples wait for four completed frame increments. The real-game baseline explicitly selects WebGL2, checks the selected backend, races Singapore at night and uses the existing park/hud/orbit/light hooks. Its rAF wall-window timing differs from the spike's frame-delta protocol, which limits direct numerical interpretation. Outputs are PNGs and results JSON; small-file blank detection is a heuristic, and recorded errors produce a failing exit. An unrecognized mode writes metadata without either arm, so a produced JSON file alone does not establish a completed capture.

capture-m8.mjs drives five sequential real-game shots: Monza and Singapore for TLX and GLX, plus an SSAO diagnostic view. Each new page gets explicit backend preferences; TLX forces WebGL2. It waits for the game and track, asserts backend identity, parks, optionally records post-chain state and captures a fixed viewport clip. Per-shot failures become result entries, and any thrown shot, small PNG or recorded error sets a failing exit code. Browser and server cleanup are explicit. The static f1-dev-tools unit source consumes extracted portions to check GLX selection/browser cleanup, failed-shot verdicts/server cleanup and decoded traversal rejection in the side-world server. These existing tests were read, not run.

Both capture drivers discover Chromium through fixed legacy locations before falling back to Playwright. They create directories and overwrite named captures/results when executed. They are retained experiment tools, outside the normal test-runner API; no execution or actual image acceptance was attempted here.

## Geometry and physics probes

build-geometry.cjs is the producer for the physics JSON contract. It reads TRACK_VM and circuit inventory from the manifest, expands the circuit sentinel, executes sources in a Node VM with a raw-buffer GLX stub, exposes globals by rewriting top-level const declarations, and looks up the requested track. Tracks.build resolves through LSP to js/track/tracks.js. A full-detail daytime build exports only road positions/normals/indices and centreline positions/tangents/half-widths, with lap length and node count. Positions must be nonempty and finite; this is not comprehensive mesh validation. The output excludes terrain and props. The ignore file keeps generated geometry untracked, and the default geometry dependency is absent in this checkout. No generator was run.

The physics README and DEEP-DIVE.md must be read together. The follow-up retracts the original apparent twofold understeer: the sample was a car already off the road without wheel contact. It also corrects the load statement: the clamp scales with wheel load while realistic tyre load sensitivity remains absent. The retained reason to keep bespoke player handling is structural binary grip and a missing stable, progressive friction-ellipse response. The handover and side-world numbers are historical measurements, not current regression passes.

The browser side-world pair measures a narrowly isolated CPU/WASM tax. deep-sideworld.js imports Rapier, fetches generated geometry, builds a fixed road trimesh, mirrors 22 scripted cars at 45–55 m/s and drops 100 seeded debris. At a fixed 1/60 step it separately times pose writes, world stepping and 100 seven-component pose readbacks. Sixty warmup steps precede 600 samples, batched five per setTimeout. __sideworld exposes ready/done/error/result for deep-sideworld-run.mjs, which hosts the page, waits up to 240 seconds and prints timings, JSON and JS heap deltas. Its measurement server adds COOP/COEP to improve timer precision; those headers differ from the production hosting assumption. Browser and server close in finally; the page's world relies on page lifetime rather than explicit free. Console errors and nonfinite readback are reported, not universal failing verdicts.

The side-world statistics exclude rendering work and WASM linear memory. The reported p95 sum adds separate phase percentiles and is not a measured percentile of total tick duration. The mobile interpretation is a desktop multiplier, not a phone measurement. Only the final readback buffer is checked for nonfinite values. These limitations matter when using the retained figures for budgets.

deep-handover.mjs uses the same road data and vendored Rapier to simulate 20 seeded moderate episodes, 20 aggressive episodes and a repeated moderate suite. It creates a dynamic cuboid at 80 km/h with matched pose/velocity, applies vertical/roll impulses and waits for touchdown plus 30 stable ticks, capped at six seconds. A flat pseudo-terrain pad approximates off-road support. It compares local nearest-node projections around predicted progress with global brute force, reports continuity/height/speed/rollover classifications and compares final float64 bit patterns. Worlds are freed. The corrected clamped flag measures whether the winning node is on the search-window edge. This remains a standalone protocol approximation; the script prints a false determinism result without a corresponding failure exit.

deep-tuning.mjs isolates vehicle behavior on a large flat cuboid. It sweeps friction/side stiffness, suspension and centre-of-mass candidates; holds rear-axle speed with a clamped controller; records radius, yaw variation, roll and limited finite checks; then probes transient response, realistic friction limits, brake calibration, midcorner braking, doubled mass and per-wheel impulse/load ratios. Optional road replication is skipped on missing geometry. Worlds are freed and observations print to stdout. A yaw-rise heuristic can label a divergent spin as a friction-ellipse signature, so the deep-dive's stability analysis is essential context.

Only the prefix of rapier-eval.mjs belongs here: vendored Rapier initialization, generated geometry loading, fixed-step world/road helpers, centreline frames, nearest-node search, chassis and four-wheel setup, scripted engine/steering inputs and the start of engine calibration. Batch 06 owns the rest of calibration and subsequent evaluation bodies. No full-script determinism or performance implementation claim is made from this prefix.
