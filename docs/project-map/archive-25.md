## Architecture contracts and historical decision

Source 1 compares migration exposure against the agent-maintained no-build runtime. Typed Apex proposes authored GameCtx, RendererBackend and SceneryApi declarations, incremental checkJs, an esbuild shadow build, one large IIFE-to-ESM codemod, a hashed bundle cutover and eventual TypeScript domains. Its compatibility obligations include published window globals, curated circuit order because stored track selection is positional, dynamic-backend fetch failure falling back honestly, and descriptor installation preserving gfx === GLX for monkey-patching specs. It keeps physics integration blocks intact, gates phase boundaries on bit-stable characterization and retains semantic speed, geometry and documentation guards. Proposed helper/module names are plans, not claims of present files.

Bedrock instead hardens IIFEs: derive evaluation edges with espree/eslint-scope, generate coordinated shell/manifest/precache outputs with a byte-identical bootstrap, type script globals incrementally, seal the façade, snapshot its member kinds and carve six singly owned state domains. The proposed domains are camera, tuning, race, world, garage and debug; side effects become named verbs. Renderer installation fills omitted port members with explicit undefined so stale GLX closures cannot survive descriptor copying. A scanner may miss computed references; ownership scans and type adoption need baselines and ratchets rather than pretending complete static proof.

The two judges independently rank Bedrock first (44 and 43), Graphline second (34 and 30), and Typed Apex third (27 each). Their five axes are agent safety, no-build ethos, migration risk, determinism and payoff per effort. They favor a one-PR rollback with the existing suite valid over either a freeze-window codemod or a long hybrid module regime. The synthesis adopts Bedrock with Typed Apex's precise interfaces and Graphline's dependency-truth/topological-order check. It stages observation, types, manifest generation, renderer port, isolated sealing/state carves and closure of named guard gaps. These include arc-source allowlisting, vertex ratchets and receive-side network authority checks.

The decision preserves characterization, module-size, speed invariants, scenery contracts, geometry parity and documentation guards. It explicitly leaves cache-version rituals and mixed working-tree browser runs as acknowledged costs, with module migration an escalation if those become the dominant observed failure mode. Its timing estimates and tooling budgets are dated proposals; they are not present performance evidence. Current AGENTS.md remains the workflow authority.

## Test taxonomy, relocation and critique

Source 2 separates meaningful assertions from capture galleries and from costly duplication. The proposed foundation group removes circuit construction checks from driving physics and routes circuit/track changes to them; gallery captures become on-demand. It proposes splitting agent-view and career monoliths, separating foundation diagnostics from hooks and parts geometry from parts statistics, and merging redundant HUD/desktop/manual capture loops. Its ordered migration is merge, regroup/rename, relocate, then split. The relocation design accounts for fixture imports, helper-relative paths, snapshot directories, the physics baseline, dynamic tool imports, group/docs agreement, scan regexes and CI filters. These are historical coupling inventories, not instructions to repeat the moves now.

The same source retains an adversarial feasibility review that materially qualifies its design. A reusable workflow inherits its caller's event name, so comparing event_name to workflow_call cannot exclude deploy calls. The caller aggregates all called jobs, making an advisory job capable of blocking deploy even without an explicit needs edge. First-push zero bases, unsupported dispatch events, human-output parsing, group globs and list-count extraction also need deliberate handling. A twelve-test cap cannot fit typical selected groups; retries and per-test timeouts invalidate all-pass arithmetic. Shell/version bumps would force fallback on final reviewed pushes, while fallback merely duplicates existing guards and leaves several groups uncovered.

The critique also catches coverage loss hidden by a deduplication claim: removing collision/drift/offtrack from behaviour loses those checks for driving-model selections unless routing changes; removing hooks from API loses coverage for assets/data changes. Visual skip gates and duplicated lighting A/B membership further weaken budget accounting. Consequently the source's selector design and its stated safety story must be read together, not quoted as an approved implementation.
