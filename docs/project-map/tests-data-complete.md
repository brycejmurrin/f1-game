# tests/data complete static map

Snapshot: 2026-10-27. The assigned scope contains **221 original tracked files, 2,150,456 bytes**: 220 JSON/GeoJSON documents and one historical lighting TXT fixture. `tests-data-evidence.json` is the per-file ledger: SHA-256, size, exact half-open raw byte ranges, recursive node counts/types, object shapes, numeric ranges, semantic category, producer/consumer contract, literal references and relationship checks. All 111,905 parsed nodes were traversed. No JSON parse, duplicate-key, non-finite-number or implemented domain-shape errors were found. These are static results; no tests, browser, generator or fixture code ran.

**Read methods are deliberately distinct.** All 214 small/narrative files were fully raw-read in 220 individually returned pages of at most 8,500 bytes. This includes every one of the 341 query/expect rows across 36 routing files, all landmark rationales, exception policies, fragment files and every byte of the historical TXT. Seven large numeric/enum tables were completely decoded and recursively traversed, with metadata read separately; their numeric cells were not manually prose-read. Those tables are the triangle-count golden, GeoJSON reference, generated impact graph, both timing tables and both defaults exports. JSON records the actual paths and ranges. Missing, archived and historical path strings are confined to the evidence JSON.

Repository AGENTS.md and the code-nav skill were read. Production symbol navigation used the attached apex-lsp definition lookup for `FrameLights`; filename/fixture associations used static text search. Literal references can include comments and docs and do not prove a runtime dependency. Directory enumeration and constructed paths explain why individual fragment or landmark filenames often have no direct reader string.

## Ratchets and impact relationships

`tests/data/ratchets.json` holds ten file entries and seventeen tree metrics. Eighty-five branch fragments carry signed deltas in `files` and/or `tree`; sum them into the base to obtain effective ceilings. The evidence JSON records that complete static sum. The owning ratchet tool writes branch deltas, absorbs ordinary small growth according to its reason policy, and folds fragments into the base. Do not hand-edit these generated files or treat a negative delta as a standalone ceiling. Default stale headroom is max(60, 4% of ceiling); an explicit slack may tighten this but cannot loosen it. CSS-token debt, implicit assertions, twin debt and zero-reference modules include exact/slack-zero ratchets. Some source-pin metrics use diff-relative inherited-overage treatment outside absolute CI mode; static sum is not a current-source verdict.

The generated impact graph contains **495 source files, 4,123 function keys and 8,751 test edges**. Every source/target path exists at the snapshot. Twenty-four authored pin fragments merge by set union and sorted order, including special `narrow`, wildcard and named-function keys. Every fragment edge is already present in the generated map. The selector consumes `narrow` browser-spec pins only when `narrowOnly` is true and the target exists; function associations discovered by lexical source path plus call spelling are weaker than behavioral coverage. Fragment provenance and every source/function/test relationship are retained in JSON.

## Routing expectation semantics

The 36 query files contain realistic requests, shorthand, positives and named-neighbor near misses. File stem is the source category; `expect` is the scored target and need not equal the source. The evaluator accepts the first Skill call or SKILL.md read before other tools as strict routing; optional grace records late routing, aliases normalize merged skills and repeated runs use majority with agreement. Expectations not present in the available skill set are scored as correct when no skill fires (subagent/no-skill route), so available skills from the evaluation checkout materially affect meaning. These strings are test input, never instructions authorizing this audit to deploy, browse, mutate or delegate.

The nominal “eight queries, five positive / three near miss” header is descriptive history, not current cardinality: there are 341 rows with per-file counts in the ledger. Some fixtures retain pre-fold neighbors such as game-feel, phone-browser, check/ship/handoff routes and deployment research; changing or deleting them requires route-owner review rather than treating a non-current name as dead data.
