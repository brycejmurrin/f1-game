`us` checks emulated/native installation exclusivity and offers `installed`, copied `capabilities`, and session summaries. It wraps requestSession/offerSession, strips synthetic gaze features before calling native XR, validates profile gaze support, and attaches sessions using local-floor then local/unbounded anchor fallback. Required synthetic gaze failures reject/end the session; optional failures may warn and retain native behavior.

Per-session records own reversible patches, listeners, frame state, bindings, source snapshots, reference-space metadata, pending input events and hit-test subscriptions. Full mode substitutes controller/hand/playback sources and suppresses original input events. Gaze-only retains native sources/viewer pose and adds synthetic gaze. Input facades expose stable spaces/gamepad values and optional hand maps. Visibility gates synthetic sources. Frame preparation advances remote/playback state once per frame, dispatches source/button transitions, and updates hit tests; three consecutive preparation failures mark support unhealthy while preserving the application's callback.

Native frame hooks cover getPose/getViewerPose/fillPoses, joint poses/radii, anchors and hit tests. Controlled-space queries reject cross-session or inactive-frame access; unrelated spaces delegate. Viewer overrides preserve browser view objects and relative eye transforms through reversible transform getters. Offset-space metadata composes matrices. Anchor transforms convert to the native anchor; moving synthetic hit-test spaces resubscribe backing native sources with motion thresholds and bounded backoff. Cancellation/end/uninstall cancels backing sources, removes listeners, restores descriptors and player event context, clears maps/queues and force-releases remote input when the last session detaches. None of this native-override API is invoked by the inspected Apex fixture.

`XRDevice` shares the application's canvas: saves parent/dimensions/z-index, mounts it into runtime container, sizes to window, and restores it on session end (plus resize event). Viewport cache yields half-width eyes in stereo; with stereo off the right eye width is zero. Each frame advances remote controls/playback or live inputs, pending visibility and reference-space-reset events, updates viewer/eye matrices and optional visibility mask. `recenter()` shifts horizontal position/yaw and controllers/hands then queues resets. `installRuntime({forceInstall:true})` replaces navigator.xr, UA, WebXR globals and makeXRCompatible; optional layers injection is distinct from its normal XRWebGLBinding. `uninstallRuntime()` restores captured state. Runtime and native override reject simultaneous installation.

## Apex integration and test boundary

`tests/vendor/README.md` is the provenance/upgrade authority: pinned IWER 2.5.0 copied from npm build; MIT IWER plus embedded Apache-2.0 layers/helpers, whose attributions must survive recopying. Sources cited there are upstream docs/repository and MDN offset-reference-space contract. This map performed no network verification. The npm manifest currently permits `^2.5.0`, while the actual test script filename and fixture version remain explicitly pinned.

`tests/helpers/iwer-install.mjs` loads the UMD with addInitScript before navigation, then serializes `installIwerFixture`: sets TLX forceGL/three/LOW, constructs `XRDevice(metaQuest3)`, force-installs and enables stereo unless explicitly disabled. Exposes `__iwerDevice` and `__iwerInstall`. Missing UMD exports produce an explicit diagnostic. Native/stub navigator.xr makes forceInstall necessary.

The fixture adapts only version 2.5.0: wraps XRReferenceSpace.getOffsetReferenceSpace to pass `transform.matrix` at the emulator's internal array boundary. `__apexMatrixAdapter` prevents double wrapping. The unadapted defect and its definitions lie outside this group's read range; their behavior is evidenced by the fully read fixture and actual-vendor regression test source. `tests/unit/xr-phase0.test.mjs:804` constructs real vendor spaces/frame/transforms, pins unadapted NaNs, stubs only device installation, installs the adapter twice, and asserts finite centered viewer/stereo midpoint, .064 IPD and negative nested .2 vertical offset. These assertions were inspected, **not run**.

Attached LSP resolved `XrSession` to `js/xr/xr-session.js` and `recenter` to line 335: production constructs a standard XRRigidTransform and passes it to getOffsetReferenceSpace; outside-frame calls queue pending recenter. The LSP definition result used module-file fallback and explicitly left caller coverage unverified. The fix belongs at the test emulator boundary, not production/native XR.

Helper waitXrReady requires XrBoot binding before session creation; waitXrFrames uses one page evaluation and a Node watchdog instead of competing XR rAF callbacks (strict `fc > base + need`). waitWhilePresenting handles post-session predicates; canvas capture uses window rAF/toDataURL; sampleXrEye samples only inside an active session frame. Its GLX layer lookup may be null; eyeFrames accepts that path.

`tests/specs/vr-emulated.spec.js` consumes the fixture for ENTER/EXIT/reentry, seated physical movement/recenter, controller menu/driving mapping, disconnect/visibility pause, paused presentations, WebGPU fallback, flat-loop/camera restoration, backend reload selection and stereo/canvas checks. `tests/specs/xr-plan.spec.js` checks armed WebGL2 boot and no-XRGPUBinding fallback; reported xrCompatible is annotated rather than asserted. Both skip when pinned file is absent. `playwright.config.js` has a dedicated xr-emulated project with software-GL launch configuration. `tests/unit/ci-gate-selection.test.mjs` expects helper/vendor changes to select XR gates; phase0 asserts the vendor is present and index.html does not reference it.

Production consumes standard WebXR through XrSession/XrBoot, not IWER globals. The README forbids shipping tests/vendor on index.html; unit canary enforces that textual boundary. Emulation proves contract/lifecycle coverage only: real Quest GPU, XRGPUBinding, multiview, foveation, MSAA and headset timing remain outside evidence.

## Maintenance and limits

Retain this used test dependency. Upgrade by bumping npm, recopying/renaming the pinned build, updating helper and path canary, preserving both license families, and revisiting/removing the offset adapter against the new version. Inspect native override's restoration and layers GL state preservation when upgrading; their inclusion in the bundle does not establish Apex usage or correctness on devices.

No vendor evaluation, tests, browser/device session, network requests, source edits, staging or commits were performed. Only this map and its evidence ledger were written.
