## Browser fixture and VM execution model

`fixtures.js` is the runner seam. Its module-load `APEX_VM_PAGE === "1"` switch selects either Playwright `base.extend` or `makeVmTest`; importing the file still imports Playwright's `expect`, but `vm-page.js` loads `node:test` lazily. Browser context installation adds `__TEST_MODE`, optional `APEX_LOG`, native GLX preference, JSON `"off"` tyre wear and wind, then empty Jolpica/OpenF1 responses. These are deliberate test settings, not evidence of shipped defaults. Page-level realistic API mocks override the context-level empty fixtures where installed. `racePage` does a virgin navigation and fixed 45-second hook wait. Fresh `loadTrack` optionally stops rasterization before the build, synchronizes the factory McLaren seat, awaits `race`, waits for the track and calls `go`.

Browser `sharedTest` creates one worker-scoped context/page and performs one initial hook wait (60 seconds). Its per-test viewport update and `resetSharedPage` clear held input, wake rasterization, set warning logs, unfreeze, choose chase camera, zero roadFollow and the pause-menu racing-line slider, and close dialogs. It does not restore physics tuning generally, user settings, career state or the storage cache. Shared `loadTrack` waits on a per-start promise flag so the previous non-null track cannot satisfy the next build. A spec asserting boot, migration, service worker or persistent defaults needs the virgin fixture. `shared-page.js` adds UI teardown and cache-aware storage preparation for consumers that deliberately share pages; it is not an automatic full reset.

Browser console capture begins at context/page creation and retains a nominal 400-line console tail (page errors append independently). On an unexpected result the hooks attach up to 120 console lines, best-effort `physState/probe/timing/lightState/info`, and up to 80 Log records. Opt-in coverage stops before page teardown; a final best-effort hook quiets rasterization. Shared coverage starts after boot and stops once per worker, whereas virgin-page coverage starts through context installation. Diagnostics, coverage writes and teardown quieting are best-effort and do not replace a test assertion.

`vm-page.js` compiles function text in the game's realm, JSON-round-trips its single argument and copies results back with `toHost`. The copier preserves nonfinite numeric primitives, cycles, Date, RegExp, Error name/message, Map and Set; typed-array views become arrays. It does not preserve arbitrary prototypes. `evaluate` pumps due timers and rAF while awaiting returned promises, bounded by a 60-second wall-clock watchdog; renderer exceptions get a browser-required diagnostic. `waitForFunction` repeatedly evaluates, flushes due timers and yields to `setImmediate`; its `polling` option is not a real interval. `waitForTimeout` also only flushes/yields. `goto` boots once and later shallow-resets; `reload` closes and boots again. Viewport changes are recorded only, URL is fixed, and DOM selectors, routing, screenshots, mouse, keyboard and clock objects throw explicit unsupported errors. The adapter supplies no graphics or stubbed network data, and game-vm already has its boot circuit available.

The VM declaration adapter discovers requested fixtures from destructured callback source (or explicit `fixtureNames`). It builds a fixed set: page/racePage/loadTrack/pageErrors/consoleLines/context/browserName/viewport. Hooks inherit through describe scopes; cleanup runs even after body rejection and multiple errors become AggregateError. Shared pages persist across test bodies. `test.extend` is a no-op, serial/parallel/only describe aliases do not implement Playwright scheduling, `test.slow` and test-info `setTimeout` are no-ops, fail declarations become Node todo, and runtime boolean skip/fixme calls return without skipping. Therefore API portability and declaration portability are separate from browser equivalence.

## Evidence-backed comment discrepancies and bounded risks

These are static findings, not reproduced failures. No implementation was changed.

1. **Log export comment is stale.** `await-track-build.js:114` says Log is lexical and “not window.Log”; actual `js/core/log.js:210` explicitly exports it, confirmed by LSP and direct source reading. Both its lexical boot read and `fixtures.js:305` window.Log failure-ring read are valid today. The misleading comment must not be used to diagnose a missing failure ring.
2. **Shared loader overstates frame evidence.** `fixtures.js:500–502` promises “one presented frame”; L515 actually awaits two requestAnimationFrame callbacks and does not read any presentation signal. `agent-view-ready.js:7–23` itself explains why rAF ticks can occur while rendering is skipped. This loader establishes callback turns after race completion, not independently verified presentation.
3. **VM reload realm reuse risk.** `vm-page.js:222–229` creates a new handle/context on reload, but `_runner` is cached at L240–246 and neither reload nor close resets it. After a prior evaluate, subsequent evaluate can invoke the old realm's compiled runner while timer pumping/drain use the new handle. “A real second boot” describes the new handle but does not establish evaluate isolation after reload.
4. **VM/browser init-script restriction is overstated.** `vm-page.js:191–192` says registering before first goto is required “as Playwright requires too.” This adapter intentionally refuses post-boot registration; that is its own restriction. The file's documented shallow goto model already prevents claiming general navigation equivalence. No external API behavior was exercised in this lane.
5. **Several timing comments are historical, not current contracts.** `fixtures.js:224–225` says racePage waits “up to 10 s” although L230 uses BOOT_MS=45000. `await-track-build.js:27–30` says the test timeout is the progress backstop, while L40/L75–79 now add the explicit 300s hard cap as well. `track-helpers.js:132` says explicit step ticks draw a GPU frame, but the subsequent rendered-clock/presentation waits supply the actual frame evidence.
6. **Some “one source” claims have narrower scope.** `garage-sheet.js:13–21` and `shared-page.js:215–223` contain the same waitGarageSheet implementation. The extracted module avoids runner imports, but both definitions remain and can drift. `camera-rig.mjs` says bank is exercised in its introduction while synthTracks.banking at L76 always returns zero dy/roll; elevation/ground clamps are modeled, real bank sampling is not.
7. **Fault/coverage names are stronger than their units/isolation.** `storage-faults.mjs:26–27` calls quota encoded bytes, but L50 compares JS key/value `.length` for one item, without UTF-8 encoding or aggregate storage accounting. `js-coverage.js:32–33` says port suffix ensures two runs never clobber; L59–61 writes deterministic sanitized labels without exclusive creation, so this requires distinct ports/labels.
8. **Soft screenshot shape differs by backend.** `soft-capture.js:42–56` returns raw overlay PNG/JPEG when #game-soft exists; `shotOpts` are only passed to the fallback page screenshot. A caller's clip or path is therefore not equivalent across these branches. This is observable from return/control flow, not a claim that an existing consumer needs those options.
9. **Memory “both post-warm” wording is imprecise.** `race-cycle-memory.mjs:24–25` requires laterCycle>5 so both samples are post-warm, while default later=6 compares cycle 6 with 5, and WARM_CYCLES=5 labels cycles through 5 warm-up. The actual metric is first adjacent pair beginning at the last warm-up cycle.
10. **Helper assertions establish chosen seams.** Fake GL healthy shader statuses do not establish shader validity, mini-dom's auto-created elements cannot detect absent shell ids, VM no-op declaration features cannot establish Playwright scheduling, and source regex extractors cannot establish dynamic runtime wiring. These limits follow implementation branches above and should be preserved when interpreting downstream green checks.

Parent verification remains responsible for documentation integrity checks and any integration/commit action. This lane ran neither those checks nor the mapped workloads.
