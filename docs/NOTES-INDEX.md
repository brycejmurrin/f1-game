# Apex 26 — notes, research and archive index

The second half of [README.md](README.md), split out 2026-10-26 so the start page
stays short. Nothing here is required reading: open a note when a skill, a tool
or another doc cites it. Live records first (`notes/`, `research/`), then
provenance (`archive/`), then plans.

## `notes/` — the dated ledgers

Measurements, defect registers and campaign records. **They are dated by
design**: a note is what was true when it was measured, and it is cited for its
evidence, never for current structure. Path-checked only — no guard counts
anything in here.
A note that REPLACES another starts a line with `Supersedes:` and links the
old note; the old one gets a `Superseded by:` line linking back, and the built
table flags it superseded — `docs-integrity.test.mjs` holds the pair, so an agent grepping
`docs/` never meets two live answers. Obsidian works as a reader of this tree
(open `docs/` as a vault, "Use [[Wikilinks]]" OFF; `.obsidian/` is gitignored):
[notes/SECOND-BRAIN-2026-10-14.md](notes/SECOND-BRAIN-2026-10-14.md).

**The notes table:** run `node tools/docs/knowledge-gc.mjs --index`, then open `artifacts/NOTES-TABLE.md`.

It lists each note's kind, re-measure date, cited or not and a one-line summary.
It is built, never committed (the artifact is gitignored). A committed copy sorted newest-first
made every note-adding PR conflict with every other (issue #5347). A note's
row comes from its own header lines: `Kind:`, `Re-measure-by:` and an optional
`Summary:` (the H1 otherwise), so a new note touches no shared file.
