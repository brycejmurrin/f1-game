## Ranked leftovers

Act in this order. Each row is a **countable** mechanism; GPU ms stay
unverified on this box.

### 1. TLX shadow copies the full instance set (High, TLX-only)

`js/game.js` `_castPropBatchesShadow` does the right thing: builds light-
frustum planes from `gfx.shadowCullVP` and calls
`gfx.castShadowInstanced(batch, gfx.cullInstances(batch, planes))`.

GLX and WGX honour the `count` argument (draw / upload only the culled
prefix). TLX does not:

- `tlx.js` `castShadowInstanced(batch)` takes **one** argument and forwards
  to `tlx-shadow.js` `castInstanced(batch)`.
- `castInstanced` sets `n = batch.instances` and memcpy's `srcMatrices`
  (or walks `imesh`) for the **full** set. Comment on that function
  correctly says `batch.visible` is the *camera* cull and must not be
  reused — it then skips the *light-frustum* count the caller already
  computed.

On vegas that is up to **78,951** instance matrices per shadow pass (sun
snap + each lamp pass that casts props). GLX/WGX already pay the culled
subset.

**Fix direction:** thread `count` through `castShadowInstanced(batch, count)`
and copy only `min(count, instances)` from the **already-repacked** buffer
`cullInstances` just wrote (or run the same AABB cells against the light
planes, which `cullInstances` already did). Do not use `batch.visible` from
the prior lit pass. Bit-identical to GLX/WGX if the same planes are used.

Context7 `/mrdoob/three.js`: after `setMatrixAt`, call
`computeBoundingSphere()` if `frustumCulled` stays default-on (r151+).
TLX currently sets `frustumCulled = false` on InstancedMesh, the mesh pool,
and shadow casters — so three will not save you. CPU cell cull is the real
gate; honouring `count` in the shadow pool is the missing half.

### 2. WGX shadow model: N `writeBuffer`s per pass (High, WGX)

Lit draws already follow WebGPU Fundamentals
([optimization lesson](https://webgpufundamentals.org/webgpu/lessons/webgpu-optimization.html)):
fill a large typed array, **one** `queue.writeBuffer`, dynamic offsets at
`setBindGroup`.

Shadow still does the old pattern. `_writeShadowModel` writes 16 floats to
`shadowModelUBO` at `slot * 256` on **every** `castShadow` /
`castShadowChunked` / `castShadowInstanced`. The ring (`SHADOW_SLOTS = 40`,
stride 256) is already allocated. `game.js` can issue road + terrain +
props + 22 cars + instanced batches in one pass.

`wgx.js` still has **37** `writeBuffer` call sites. Most are once-per-pass
post UBOs (necessary). The dense leftover is this shadow ring.

**Fix direction:** copy the lit `_writeDraw` / `_flushDrawUBO` shape —
CPU `shadowModelRing`, `_shadowSetModel` only bumps the slot, one
`writeBuffer(shadowModelUBO, 0, ring, 0, slot * STRIDE_F32)` in
`shadowEnd` (or immediately before `shadowPass.end()`, same “queue before
submit” rule the lit flush already documents). Mapped transfer +
`copyBufferToBuffer` is the Fundamentals step *after* that, not the first
cut.

TinyFish search (2026-08-18) still surfaces the same queue-timeline rule:
`writeBuffer` is consumed before recorded draws run — which is why a ring
+ one upload is safe, and why per-draw uploads of the *same* slot were the
08-17 blur/particle bug (already fixed).

### 3. Boot: content-hash + trim eager dev surface (Medium, convention)

Still true, still not a code tweak:

- Global `?v=N` on every tag drops Chrome's code cache on any CSS edit
  (v8.dev *Code caching for JavaScript developers*). Per-file hashes need
  the index.html / `version.json` / `sw.js` guards updated together.
- `apex.js` + `agentview*` = 350 KB no player executes. `sw.js` install
  builds a **full** code cache of the precache, so this is a phone-memory
  argument, not a parse-time one.
- `defer` is still not a one-attribute change: nine modules branch on
  `readyState === "loading"`. Flip those to `!== "complete"` *first*,
  prove green, then consider `defer`.

LIST points lazy-load is **done**. Circuit files stay 29% of the wall for
one-of-forty data; parse is cheap, PWA memory is the remaining reason to
defer them.

### 4. DebrisWorld skip rarely fires mid-race (Medium, physics)

Idle skip is in `debrisworld.js` `step()`. The header says it **rarely**
engages during a race: marbles stay `live` for `MARBLE_REST_DESPAWN_S`
after settling, and a sleep-only skip freezes kinematic mirrors (cars
drive over settled marbles that `marbleGrip()` still counts). 2026-08-13
physics profile: ~16% inclusive in the Rapier side-world.

**Fix direction (unsafe unless both are hoisted):** keep mirror posing +
marble/panel despawn bookkeeping on the JS side; skip only `world.step`.
Do not ship a sleep-only gate. Re-profile with
`profile-gameloop.mjs vegas physics` when Playwright occupancy is clear.

`pairContact` + `resolveCollisions` (~9.5% in that profile) already have
the cheap reject + arc buckets. Further cuts there are solver work, not
a missed pre-reject.
