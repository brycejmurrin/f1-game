# Learn module proposal — Where did the time go?

**Learning objective.** Compare two traces at the same estimated distance. Identify brake onset, minimum observed speed and throttle recovery, then describe where the time difference grows or shrinks. Use a synthetic pair first and transfer that skill to Data Hub Telemetry.

## Existing Data Hub behavior

Deploy branch audited at [`ceb304af`](https://github.com/brycejmurrin/f1-game/tree/ceb304af1a413a0fbb910805e8a61b31a3661cf1). The Telemetry tab uses OpenF1. The first driver is the reference. Choosing a second driver enables comparison, and the two lanes draw full traces. The loader fetches each driver's fastest lap in the selected session, requests car data around its boundaries, trims the trace and loads location data for the map. Braking Duel already accepts a distance window, reports the three markers and lets the user jump to their estimated times. [Hub](https://github.com/brycejmurrin/f1-game/blob/ceb304af1a413a0fbb910805e8a61b31a3661cf1/js/data/hub.js#L553) · [Selection](https://github.com/brycejmurrin/f1-game/blob/ceb304af1a413a0fbb910805e8a61b31a3661cf1/js/data/telemetry.js#L56) · [Fetch and clip](https://github.com/brycejmurrin/f1-game/blob/ceb304af1a413a0fbb910805e8a61b31a3661cf1/js/data/telemetry.js#L200) · [Transport and Braking Duel](https://github.com/brycejmurrin/f1-game/blob/ceb304af1a413a0fbb910805e8a61b31a3661cf1/js/data/telemetry-player.js#L45)

Use the existing model for distance and markers to preserve consistency between Learn and Data Hub. `cumDist` uses right-endpoint integration, so for each interval add `speed[i] / 3.6 × (t[i] − t[i−1])` in metres. `timeAtDist` linearly interpolates time on the resulting distance grid. Braking Duel steps across the chosen section in 128 intervals and reads the nearest source sample. Brake onset is armed by a sample at or below 10 and needs two distinct samples at or above 20. After brake onset, throttle recovery is armed at or below 70 and needs two distinct samples at or above 90. Marker positions relate to that grid and can precede the timestamps in the nearest-sample rows. [Distance and markers](https://github.com/brycejmurrin/f1-game/blob/ceb304af1a413a0fbb910805e8a61b31a3661cf1/js/data/telemetry-model.js#L32) · [Nearest sample](https://github.com/brycejmurrin/f1-game/blob/ceb304af1a413a0fbb910805e8a61b31a3661cf1/js/data/telemetry-model.js#L337)

## Five-minute flow

1. Show two labeled speed traces and a brake-state strip, starting on a time scale. Ask which lane reaches the chosen exit distance first. Let the learner change to distance, with the same samples and the same section.
2. In distance view, select 10–90 m and choose one checkpoint from brake onset, minimum speed or throttle recovery. Move both lanes' readouts to the same estimated distance. An aligned time-delta strip plots `t_B(d) − t_A(d)`, positive when B reaches that distance later. Keep sign, reference lane, and units visible.
3. Reveal the comparison at the end of the section. B brakes later and briefly leads, but its minimum speed is lower and it reaches 90 m around 0.13 s after A. Ask the learner to choose a conclusion that the trace supports. Feedback should distinguish describing a pattern from attributing a loss solely to brake timing.
4. Offer **Open Data Hub Telemetry** after the worked example, using the existing Hub tab route and retaining the current session selection when present. Tell the learner to select two drivers from the same completed qualifying session and pick a visible braking section within both traces. A return to Learn restores the worked-example checkpoint. The offline example and its feedback remain available when the provider has no samples or the Hub request fails.

The first version can link to the Hub and reuse `DataTelemetryModel` in Learn without requiring a new backend or a live fetch. A later opt-in **Analyze this section in Learn** action can pass the current comparison window and normalized rows in memory through a narrow handoff. Include session, driver and lap identifiers, units, source and return focus. Reuse the existing Hub API cache and request budget. The following rows are authored, with no real driver identities or claims about real braking performance. Every row is 0.25 seconds apart. Each lane starts at the same synthetic distance origin. Speed is in km/h, brake is an on/off indicator encoded as 0 or 100, and throttle is the feed-style percentage.

To reproduce, map each lane to `{car: [{t, speed, brake, throttle}, ...]}` and pass `(A, B, 10, 90)` to `DataTelemetryModel.brakingDuel`. At 0.50 s, A has traveled 28.75 m and B 30.00 m. At 90 m, A's interpolated time is 1.7916667 s and B's is 1.925 s. Since both reach 10 m at 0.1666667 s, the change is +0.1333333 s. Display about +0.13 s with an estimate label. The illustrative markers from the deployed grid are about 22 vs 36 m for braking, 144 vs 126 km/h for minimum observed speed, and 56 vs 65 m for throttle recovery. Raw brake samples first report on at 0.50 and 0.75 s respectively. Use these raw times to teach what a sample says and the grid markers to teach where the model places it. ## Interpretation for real sessions

- FIA event timing and sector analysis provide published sector and lap times and speed figures. Use those documents as references for official timing. The course's distance-aligned delta derives from sampled speeds and may drift relative to surveyed corner or timing-line positions. Confirm driver, session and lap identities before any official checkpoint comparison. [FIA Las Vegas event timing](https://www.fia.com/events/fia-formula-one-world-championship/season-2026/las-vegas-grand-prix/eventtiming-information) · [FIA race sector analysis](https://www.fia.com/sites/default/files/2026_21_usa_f1_r0_timing_racesectoranalysis_v01.pdf)
- OpenF1 documents about 3.7 Hz for car data, speed in km/h, brake as pressed or released, and throttle as percentage of maximum engine power being used. Use “brake on” and “reported throttle.” Omit claims about brake pressure, exact apex, actual power in kW or 2026 mode activation based on these fields. A named throttle recovery marker describes a threshold crossing. Differences in entry speed, line, track evolution, tyres and traffic can all affect a comparison between drivers. [OpenF1 car data](https://openf1.org/docs/#car-data)
- Validate both lanes from the alignment origin to the selected section before promising comparable distance. Braking Duel checks for gaps over 1.5 seconds inside the window, while `cumDist` alone can integrate through a long finite-speed interval before it. A Learn adapter should withhold absolute-distance claims across such a prior gap or explicitly establish a common local origin. Preserve gaps and unknown markers in charts and tables. Keep fixture ID or provider, session/driver/lap IDs, timestamps, units and alignment version with any reproducible example. Check data reuse terms before bundling any provider rows. [Coverage behavior](https://github.com/brycejmurrin/f1-game/blob/ceb304af1a413a0fbb910805e8a61b31a3661cf1/js/data/telemetry-model.js#L32) · [OpenF1 access and data ownership](https://openf1.org/)

## Accessibility and acceptance

- Start paused. Provide labeled time/distance controls, checkpoint buttons, and a native slider or numeric input. Keyboard and single click or tap can reach every checkpoint without dragging. Use lane names and distinct line styles in addition to color. Include an HTML table of current values and a textual answer summary that updates at user-selected checkpoints without a stream of announcements during playback. Preserve focus after switching axes or returning from the Hub. Check narrow phone landscape and zoom/reflow. [WCAG 2.2 keyboard, use of color and dragging criteria](https://www.w3.org/TR/WCAG22/)
- The exact fixture returns about +0.13 s change for B versus A. Swapping the reference flips the sign. A 95 m end is unavailable because B ends at 93.75 m. Replacing B's 1.00 s brake sample with null returns missing channels. A gap over 1.5 s in the window and an earlier gap since alignment each show an unavailable state and reason. A missing threshold crossing leaves that marker absent while the valid delta still displays.
- Passing the lesson requires identifying B as later at the 90 m checkpoint and explaining the conclusion with elapsed times at equal distance. A follow-up asks what the binary brake signal means and offers a “brake pressure” distractor. Inspect keyboard-only completion and the table-only answer path. Verify the Hub handoff and return with a seeded provider fixture before trying a real session.
- Node VM checks against the pinned deploy source reproduced the numeric result, swapped sign, missing channel and uncovered-end cases. Browser presentation, accessibility and the Learn-to-Hub handoff remain proposed.
