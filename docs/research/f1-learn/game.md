| Tyre grip, braking, and rotation | Vary steering slip angle, braking/throttle demand, and front brake bias. Show two axle friction circles, side-force versus slip, and front/rear utilisation. Compare neutral, trail brake, and power-on exit. | `TyreModel.lateralCurve` and `PlayerForces.tyreSat` supply accessible curve primitives. The full player step uses two axle circles, a bicycle rigid-body yaw/lateral model, front/rear tyre response asymmetry and rear-only power demand. The peak of the front curve and the normalisation used in the utilisation cue differ, so derive chart peak markers from the actual curve. Optional `WheelState.axleStep` adds longitudinal slip, wheelspin and lock, with an effective axle inertia rather than four independent corners. ## Additional rule and model opportunities

- A race-control timeline can let the learner give back an illegal position under VSC/SC and compare exemption cases. `SportingRegs.createPassWatch` tracks order and restitution; `createBlueFlagWatch` and jump-start predicates supply other scenario prompts. The game prices multiple cautioned passes as equivalent added seconds and uses a locally modeled flag state and hazard thresholds. Display the game's verdict with its assumptions, and independently cite the official exceptions and penalty guidelines. [Pass watcher](../../../js/race/sporting-regs.js#L108) · [Jump start and blue flags](../../../js/race/sporting-regs.js#L226) · [Flag thresholds](../../../js/race/race-control.js#L218)
- A racing-line and braking-envelope lab could stage sections at fixed distances, overlay curvature/speed, and scrub comparative laps. `Quali` integrates a quasi-steady speed envelope and uses a calibration against Apex AI times. Live AI is kinematic and uses different control logic from the player, so compare the same controller and starting conditions for quantitative A/B runs. [Qualifying calibration](../../../js/race/quali-model.js#L1) · [AI drive](../../../js/physics/ai-drive.js#L1) · [Curvature channels](../../../docs/PHYSICS.md#L1158)
- A visual setup demonstrator can animate brake dive, speed-dependent ride height/rake, kerb strike and plank scrape through `BodyAttitude`. It is a render-side spring/pose layer, while the core per-axle load and slip behavior lives in `PlayerForces`. Treat the visual displacement as illustration. The file `vehicle.js` supplies shared scratch bags for force calculations. [Visual body outputs](../../../js/physics/body-attitude.js#L97) · [Core force step](../../../js/physics/player-forces.js#L36) · [Scratch module](../../../js/physics/vehicle.js#L1)

## Integration priorities

For standalone lessons, start with three compact adapters covering energy eligibility, stint decisions, and friction/wake charts. Keep unit conversion and explicit model provenance at the adapter boundary. Prefer tables of scenario inputs and pure calculations where available. IIFE modules can be evaluated in their existing script order with their specific dependencies, or wrapped behind an explicit adapter. `AiDrive` evaluates against `M4`, `TyreModel` uses `PhysicsConsts`, and runtime factories such as `PlayerForces.create(G)`, `PitLane.create(G)` and `RaceControl.create(G)` integrate with live game state. Sample values immediately or copy them when source functions expose shared mutable scratch. Save full game integration for something that benefits from a fixed-input run with world interactions.
