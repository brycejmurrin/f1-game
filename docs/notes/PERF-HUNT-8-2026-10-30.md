## Research: iPhone GLX black canvas, ranked
1. **Default-framebuffer invalidation**: MED, HIGH on iOS 18.0/18.1. https://bugs.webkit.org/show_bug.cgi?id=280799
   (suspected root cause https://bugs.webkit.org/show_bug.cgi?id=274137). Fixed above. Device check: Safari Web
   Inspector, `apex26.glxInvalidate="1"` versus unset.
2. **GPU-process jetsam / a lost context that never fires an event**: MED.
   https://bugs.webkit.org/show_bug.cgi?id=300782, https://bugs.webkit.org/show_bug.cgi?id=289601,
   https://bugs.webkit.org/show_bug.cgi?id=290623. GLX self-heals (reload ×2, then the overlay) only when the event fires.
3. **Synchronous shader compile on Safari, even with KHR_parallel_shader_compile**: LOW–MED (a long freeze, not
   black for good). https://lists.webkit.org/pipermail/webkit-unassigned/2023-February/1084921.html,
   https://github.com/mrdoob/three.js/issues/16321
4. RGBA16F targets (https://bugs.webkit.org/show_bug.cgi?id=241399), linear-filtered float textures
   (https://bugs.webkit.org/show_bug.cgi?id=264404; the only R32F, the blocker map, is NEAREST and desktop-only),
   mediump fp16 overflow, shadow samplers (https://github.com/playcanvas/engine/issues/3590) and alpha:false
   (https://bugs.webkit.org/show_bug.cgi?id=183151): all LOW, already handled or not iOS-current.
