# LSP over MCP for cloud agents — measured 2026-10-18

**Decision:** `apex-lsp`, a ~250-line stdio MCP server in the repo (`tools/mcp/lsp-mcp.mjs`,
wrapper `tools/mcp/lsp-mcp.sh`). It drives TypeScript 7's native `tsc --lsp --stdio`, which ships
in the `typescript` ^7 devDependency we already have. `jsconfig.json` makes `js/` one
script project. There's nothing new to install. Tools: `lsp_definition`, `lsp_references`,
`lsp_symbols`, `lsp_hover`, `lsp_diagnostics`, each taking `Name`, `Head.member` or file+line (ONE-based).

Ask: Bryce, 2026-10-18: "agents are often searching for code via grep … can we setup a lsp? Do web
research", then "Can we setup a lsp mcp or tool".

## Why not a plugin LSP, and why not a stock bridge

| Option | Result in this container |
|---|---|
| Claude Code plugin LSP (`.lsp.json`) | Does not start in cloud sessions ([code-intelligence docs](https://code.claude.com/docs/en/plugins/code-intelligence)). Project `.mcp.json` servers do (apex-tools proves it). |
| [isaacphi/mcp-language-server](https://github.com/isaacphi/mcp-language-server) v0.1.1 + `tsc --lsp` (TS 7.0.2) | **Fails to initialize**: it sends `semanticTokens.requests.range: null` and tsgo answers `InvalidParams: null value is not allowed for field "range"`. |
| mcp-language-server + typescript-language-server 4.4.1 + typescript 5.9.3 | Connects (1.1 s; Go 13 MB + node 70 MB). `definition GameHud` returns the **whole IIFE body, 178,486 chars**. `definition forTeam` returns the enclosing `Liveries` IIFE, not the member. `Liveries.forTeam` and `Tracks.curvature` come back "not found" and "No references found". Name lookup goes through `workspace/symbol`, which cannot see members of a script-global IIFE. It would also need a TS 5 devDependency next to TS 7. |
| npm `ts-lsp-mcp` 0.1.3 (jaenster, last publish 2025-12) | Position-only tools (`getDefinition(file,line,col)`), no symbol-name or workspace-symbol lookup, ts-morph (TS 5 API), 75 MB of node_modules. Not the TS 7 [trophygeek/ts-lsp-mcp](https://glama.ai/mcp/servers/trophygeek/ts-lsp-mcp), which Glama lists as inactive and which isn't on npm under that name. |
| [oraios/serena](https://github.com/oraios/serena) | Not prototyped. It needs Python 3.13 + uv, fetches its own TS language server, and adds a second, heavier symbol model. TS 7 support is an open feature request ([serena#1402](https://github.com/oraios/serena/issues/1402)). |
| **`tsc --lsp --stdio` (TS 7.0.2) + in-repo bridge** | **Works** (below). `tsc --lsp --stdio` is the RC-and-later spelling of the preview's `tsgo --lsp` ([TS 7 announcement coverage](https://visualstudiomagazine.com/articles/2026/07/08/typescript-7-arrives-to-rock-vs-code-with-go-powered-speed.aspx), [TypeScript blog](https://devblogs.microsoft.com/typescript/?p=5246)). Its `initialize` advertises definition, references, workspaceSymbol, hover, rename, callHierarchy and diagnostic providers. |

`typescript` 7.0.2 has no `lib/tsserver.js`, so `typescript-language-server` cannot use it. The bin
`tsc` execs the native `typescript-linux-x64` binary.

## How the bridge resolves this codebase

- tsgo's `workspace/symbol` only searches **open** projects. The bridge opens `js/core/log.js` once,
  which loads the jsconfig project (519 files).
- `Head.member` (`Liveries.forTeam`) is resolved where it is **used**. The first non-comment
  `Head.member` occurrence in `js/` becomes the query position, so the checker follows the IIFE's
  return object, including shorthand aliases: `Tracks.curvature` → `tracks.js:775` and
  `spline.js:135 function curvature`. Unused members fall back to `workspace/symbol`, narrowed to the
  file that declares `Head`.
- Freshness: before every query, the bridge stats every `js/**/*.js` and sends
  `workspace/didChangeWatchedFiles` for whatever moved. Changed open documents are closed. There's no
  stored index.
- Output is one `file:line:col  <source line>` row per hit, capped at 200 (the `limit` argument
  raises it), never a whole function body.
- `jsconfig.json` sets `typeAcquisition.enable: false`. Without it, tsgo spawned an `npm` child
  (90 MB RSS) for automatic type acquisition.

## Iteration: two usability rounds (read-only subagent, real questions)

Round 1 (8 questions) found, and this branch fixes (each pinned in `tests/unit/lsp-mcp.test.mjs`):

| Defect | Fix |
|---|---|
| `window.X = {…}` globals (15 modules, e.g. `PhysicsConsts`, `CssZoom`) gave 0 results: the checker types them `any` | Labelled text fallback: definition at the object key, references that follow `const { x } = Head` (multi-line, renamed) and `const K = Head` aliases. `refs PhysicsConsts.MAX_RPM`: 5 → 16 rows. |
| `Foo.bar` / `GameHud.update` answered with an unrelated same-named local | An honest "not found" / "has no member", or a labelled "declared in Head's file, may not export it" |
| `def wrapS` silently picked 1 of 6 same-named functions | Lists all 6 and says so; references say which one they follow |
| A match in a comment or string became the query position | `inCommentOrString` skips it; up to 6 candidate positions are tried |
| `G.x` (the façade) was untyped | Answers from `interface GameCtx` in `types/game-ctx.d.ts` (tsgo's workspace/symbol skips `.d.ts`, so the row is found by text, then typed by the checker) |
| Hover was plaintext, the type glued to its doc | The client advertises markdown; the type comes first, then where it was asked |
| Untagged, unsorted rows; whole lines of 400+ chars | Rows `file:line:col  [def|export|alias|use] source`, the declaration ranked first, references sorted by file, a per-file summary over 40 rows, lines clipped to ~120 chars around the match, `files: true` for counts only |
| `sym clamp`: about 60 rows, mostly `const clamp = M4.clamp` | Exact names first, prefix matches labelled, aliases collapsed to a count |

Round 2 confirmed 6 of 7 fixed. It led to the head-of-destructure `[alias]` tag, exact-first `sym`, `files: true` and the
"1 definition (+2 export/alias rows)" header.

Known limits:
- A façade passed under another name (`create(ctx)`) isn't followed. In this tree `ctx` is not `G`: `wall-clamp.js` takes an explicit per-tick bag, and `agentview-raster.js` takes an agentview context, so aliasing it would invent references.
- JS parameters without JSDoc read as `any` in hover.
- Text-fallback references are labelled as such.

## Agent use: what the research says, and what it changed (wave 2)

Bryce, 2026-10-18: "Do web research about how to improve it to be more useful. Research how agents should use lsps", then "Make all improvements now".

| Finding | Source | Built |
|---|---|---|
| Definition, references and diagnostics are the operations that matter to agents (completion is noise). The loop is edit → diagnostics → navigate → fix | [Codex CLI LSP write-up](https://codex.danielvaughan.com/2026/04/25/codex-cli-lsp-integration-language-server-semantic-code-intelligence/) | `lsp_diagnostics` reports the errors an edit **introduced**. It checks one file under `// @ts-check` (the project keeps checkJs off: 39k errors), keeps only high-signal codes, and diffs against the same file at git HEAD |
| A tool that returns the **definition's code**, not just a location, saves the follow-up file read. One reliable `jump` beat multi-tool sets (IoU 24.3 vs 13.7) at ~2.7k tokens against 22–49k | [RepoNavigator, arXiv 2512.20957](https://arxiv.org/html/2512.20957) | `lsp_definition { body: true }` (40-line cap, `maxLines`) |
| A file **outline** replaces reading the file | [Serena get_symbols_overview](https://glama.ai/mcp/servers/@oraios/serena/blob/855818da6357ab37fe1d413f5451f1b7027a99e6/docs/01-about/000_intro.md), [Claude Code documentSymbol](https://claudelog.com/faqs/what-is-lsp-tool-in-claude-code/) | `lsp_outline` gives a module's exports first (the IIFE's final `return { … }`, `window.X` objects and IIFEs, an anonymous top-level IIFE's functions), each with its first source line |
| "Who calls it?" is the impact question before editing shared code | [search-tools guide](https://cc.bruniaux.com/guide/workflows/search-tools-mastery/) | `lsp_callers` groups the uses by calling function. Every reference row names its enclosing function `(Module › fn)` |
| Return high-signal, readable context, page large outputs, offer a concise/detailed switch, make errors actionable, evaluate on realistic tasks | [Anthropic, Writing tools for agents](https://www.anthropic.com/engineering/writing-tools-for-agents) | `offset` paging on references, callers, outline and symbols; `format: "concise"`; `tools/mcp/lsp-eval.mjs` (12 pinned questions, apex-lsp vs grep) |
| Agents keep grepping unless the tool is named at the moment of the search | [Locus](https://dev.to/paladini/stop-grepping-symbol-names-i-shipped-locus-a-lightweight-mcp-server-for-ai-coding-agents-2985) | `.claude/hooks/lsp-hint.py` (PreToolUse Grep/Bash, advisory, fails open) adds one line naming the call when a search pattern is a bare JS symbol |

Evidence quality: RepoNavigator is the one controlled study, it covers Python only, and it never compares against grep. The token-saving
figures in vendor posts (97 %, 900×) are unverified. Not built: rename/edit tools (agents edit with their own tools), completion
(noise), and many narrow tools (RepoNavigator's ablation).

Found while building it:
- **CommonJS-flagged globals.** Five files end in `if (typeof module !== "undefined") module.exports = X` (`ghost.js`, `ghost-share.js`, `input-ghost.js`, `forecast.js`, `share-code.js`). The checker therefore treats them as modules and their globals are invisible everywhere else: `def` from a use of `Ghost` returned 0, and `@ts-check` reported "Cannot find name 'Ghost'". They now take the same labelled text path as `window.X`, and the diagnostics filter drops TS2304/TS2552 for them.
- **JS parameters are optional to the checker.** TS2554 catches too MANY arguments, never too few.
- **TS2339 is left out.** It fires on objects that gain properties after creation (339 in game.js). TS2551, the "did you mean" form of it, is kept.

`node tools/mcp/lsp-eval.mjs` on the tree at bf2800aa: **12/12 correct**, 7,112 chars of apex-lsp output against 130,189 of grep. grep is
smaller for 4 of the 12 (hover, the Ghost exports, the body, the CommonJS users), where its answer is a single obvious line. The tool earns
its keep on references, callers, aliases and definitions behind re-exports.

## Measurements (this container, 4 cores, TS 7.0.2)

MCP client over stdio (`scratch/lsp/measure.mjs`; the same shape is the unit test):

| Call | Cold (first) | Warm | Output |
|---|---|---|---|
| `initialize` (MCP) | 50 ms | — | tsc starts lazily on the first tool call |
| `lsp_definition {symbol:"Liveries.forTeam"}` | 756 ms (project load) | 7 ms | 200 chars: `liveries.js:550` (export), `liveries.js:535 function forTeam(team)` |
| `lsp_references {symbol:"Tracks.curvature"}` | 145 ms | 20 ms | 51 refs, 17 files, 5,220 chars |
| `lsp_symbols {query:"GameHud"}` | 83 ms | 10 ms | 35 chars: `GameHud variable js/ui/hud.js:2:7` |
| `lsp_hover {symbol:"Tracks.curvature"}` | — | 5 ms | `(property) curvature: (track: any, s: any) => any` |
| after iteration: `lsp_definition Liveries.forTeam` | 1.1 s | 68 ms | candidate scan + tags; 215 chars |

RSS: server node 69 MB + native tsc 407 MB = **476 MB** (564 MB before ATA was disabled).
A one-shot shell call (`tools/mcp/lsp-mcp.sh def …`) costs 0.8–1.0 s wall.

### Against grep, same three lookups

| Lookup | grep | apex-lsp |
|---|---|---|
| where is `Liveries.forTeam` defined | `grep -rn 'Liveries\.forTeam'` → 8 uses, no definition; then a second grep for `function forTeam` (2 calls) | 1 call, 2 rows: the export and the declaration |
| all references to `Tracks.curvature` | 55 lines, 5,561 chars; 5 are comment lines; a line with 3 calls is 1 row; misses calls through an alias | 51 semantic refs (comments excluded, each call its own row, declaration included) |
| where is `GameHud` | 22 lines, 2,216 chars, mostly `GameHud.x` uses | 1 row, 35 chars |
| bonus: `Tracks.curvature` → implementation | grep stops at `tracks.js`'s shorthand `{ …, curvature, … }`; needs a second search | `lsp_definition` returns `spline.js:135 function curvature` directly |

grep stays the right tool for text, comments, CSS, HTML and regex-shaped questions.

## checkJs

`tsc -p jsconfig.json`: 0 errors with `checkJs: false` (0.7 s). With `--checkJs` (TS 7 defaults to
strict): **39,105 errors** (20,175 TS7006 implicit-any). With `--checkJs --strict false`, 2,571
(1,015 TS2339, 856 TS2304). Too noisy, so checkJs stays off and `lsp_diagnostics` reports syntax errors.

## Install

None beyond `npm install`. The SessionStart hook prints `lsp: tsc 7.0.2 (apex-lsp)`, or
`lsp: MISSING … npm install`, after a cheap `tsc --version` (~60 ms). Fresh-clone check:
`npm ci --ignore-scripts` in a new clone of this branch, then `tools/mcp/lsp-mcp.sh def
Liveries.forTeam` and `node --test tests/unit/lsp-mcp.test.mjs` (results in the PR body).
