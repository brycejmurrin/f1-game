## API style
- Base URL `https://api.x.ai/v1`; Bearer auth. A US-only endpoint `https://us.api.x.ai` serves only grok-4.7 / 4.6, costs +10 %, and has no Files, Collections or server-side tools.
- Primary interface is the **Responses API** (`POST /v1/responses`), shown with the OpenAI SDK and a custom `base_url`. Chat Completions works too (measured above).
- Structured outputs: `response_format: {type: "json_schema", ...}` (Chat) or `text.format` (Responses); tool-call arguments always match their schema. Validate anyway, some keywords are best-effort.
- Function calling, streaming (`stream=True`), citations for tool use: supported.
- **Server-side tools** (enable in the request): `web_search`, `x_search`, `code_execution`, `attachment_search`, `collections_search`, `image_generation`. Grok has no knowledge past training (grok-4.7: May 2026) unless web or X search is on.
- SDKs: the OpenAI Python/JS SDKs with `base_url="https://api.x.ai/v1"` (documented); the native `xai-sdk` (Python, gRPC). Anthropic-SDK compatibility (`/v1/messages`) is listed as legacy/deprecated by *secondary* mirrors while older xAI pages still advertise it; do not build on it.
- Zero npm dependencies needed: plain `fetch` works in Node 18+.

## Limits
Tiers by cumulative spend since 2026-01-01: Tier 0 ($0), 1 ($50), 2 ($250), 3 ($1 000), 4 ($5 000), Enterprise. Limits are per-model RPS and TPM (all tokens count, reasoning included); example grok-4.7: 150 RPS and 50M TPM at Tier 0. Over-limit returns HTTP 429; back off exponentially. The page does not give a spend cap for our account: **check the Console budget before wiring anything automatic.**

## Data policy
Official FAQ (docs.x.ai/docs/faq/security): API inputs and outputs are not used for training without explicit permission; requests and responses are stored encrypted for 30 days for abuse auditing, then deleted. Zero Data Retention is enterprise/team-wide and disables the stateful Responses API, Files, Collections and Batch. SOC 2 Type 2. Treat anything sent as leaving our control for 30 days: no keys, no private tokens, no unreleased personal data.

```js
// node 18+, no deps. Run from tools/ or CI only.
const r = await fetch("https://api.x.ai/v1/responses", {

```

## Must NOT
- Never put the key in `js/`, `css/`, `index.html`, `sw.js` or any shipped asset: the game is static GitHub Pages and everything there is public. Calls only from `tools/` or CI secrets.
- Never commit, print or paste the key; no `set -x`; do not log request headers; redact `Authorization` in any HTTP trace. Check presence with `[ -n "$GROK_API_KEY" ]` and length with `${#GROK_API_KEY}`.

- CI use needs a repository secret named `GROK_API_KEY`: adding it is Bryce's call (proposal only; `.github/workflows/**` is untouched here).

### Cursor (Cloud Agents API v1, cursor.com/docs/cloud-agent/api/endpoints)
Already probed in `CURSOR-AGENTS-API-PROBE-2026-10-19.md` and `CURSOR-SDK-RESEARCH-2026-10-20.md`; this adds only what changed.
- **Endpoints:** `POST /v1/agents` (create plus first run), `GET /v1/agents[/{id}]`, archive/unarchive/delete, `POST /v1/agents/{id}/runs` (follow-up into the same conversation and workspace), run list/get/`/stream` (SSE with `Last-Event-ID` resume)/`/cancel`, `/usage`, `/artifacts` (15-minute presigned URL), `/v1/environments`, `/v1/secrets` (values never returned), `POST /v1/sub-tokens` (one-hour user-scoped token, service-account key only).
- **Rules:** Basic or Bearer auth; one active run per agent (a second returns `409 agent_busy`); cancel is terminal; v1 webhooks are "coming soon" (v0 has them). Key types: user key, service-account key (team automation, pools), repo-scoped key (403 `repository_access` outside its repos). Keys starting `grok_` get `403 key_not_supported` for secrets, so Cursor already recognises Grok-session keys as a distinct kind.
- **Unlike Grok, Cursor agents can be messaged from outside** (follow-up runs), which is why the fleet can steer them; nothing equivalent exists for Grok.
