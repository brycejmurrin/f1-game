## API style
- Base URL `https://api.x.ai/v1`; Bearer auth. A US-only endpoint `https://us.api.x.ai` serves only grok-4.7 / 4.6, costs +10 %, and has no Files, Collections or server-side tools.
- Primary interface is the **Responses API** (`POST /v1/responses`), shown with the OpenAI SDK and a custom `base_url`. Chat Completions works too (measured above).
- Structured outputs: `response_format: {type: "json_schema", ...}` (Chat) or `text.format` (Responses); tool-call arguments always match their schema. Validate anyway, some keywords are best-effort.
- Function calling, streaming (`stream=True`), citations for tool use: supported.
- **Server-side tools** (enable in the request): `web_search`, `x_search`, `code_execution`, `attachment_search`, `collections_search`, `image_generation`. Grok has no knowledge past training (grok-4.7: May 2026) unless web or X search is on.
- SDKs: the OpenAI Python/JS SDKs with `base_url="https://api.x.ai/v1"` (documented); the native `xai-sdk` (Python, gRPC). Anthropic-SDK compatibility (`/v1/messages`) is listed as legacy/deprecated by *secondary* mirrors while older xAI pages still advertise it; do not build on it.
- Zero npm dependencies needed: plain `fetch` works in Node 18+.

## Limits
Tiers by cumulative spend since 2026-01-01: Tier 0 ($0), 1 ($50), 2 ($250), 3 ($1 000), 4 ($5 000), Enterprise. Limits are per-model RPS and TPM (all tokens count, reasoning included); example grok-4.7: 150 RPS and 50M TPM at Tier 0. Over-limit returns HTTP 429; back off exponentially. The page does not give a spend cap for our account: **check the Console budget before wiring anything automatic.**

## Data policy
Official FAQ (docs.x.ai/docs/faq/security): API inputs and outputs are not used for training without explicit permission; requests and responses are stored encrypted for 30 days for abuse auditing, then deleted. Zero Data Retention is enterprise/team-wide and disables the stateful Responses API, Files, Collections and Batch. SOC 2 Type 2. Treat anything sent as leaving our control for 30 days: no keys, no private tokens, no unreleased personal data.

## Calling it (no key value anywhere; read the env var)
```sh
# list models (free)
curl -sS https://api.x.ai/v1/models -H "Authorization: Bearer $GROK_API_KEY" | node -e 'JSON.parse(require("fs").readFileSync(0)).data.forEach(m=>console.log(m.id))'
```
```js
// node 18+, no deps. Run from tools/ or CI only.
const r = await fetch("https://api.x.ai/v1/responses", {
  method: "POST",
  headers: { Authorization: `Bearer ${process.env.GROK_API_KEY}`, "Content-Type": "application/json" },
  body: JSON.stringify({
    model: "grok-4.3",
    input: "When is the next F1 race?",
    tools: [{ type: "web_search" }],   // live web; add {type:"x_search"} for X posts
  }),
});
console.log(r.status, (await r.json()).usage);   // never log headers
```
Chat Completions body, measured working: `{"model":"grok-4.3","messages":[{"role":"user","content":"..."}],"max_tokens":16}`.

## Must NOT
- Never put the key in `js/`, `css/`, `index.html`, `sw.js` or any shipped asset: the game is static GitHub Pages and everything there is public. Calls only from `tools/` or CI secrets.
- Never commit, print or paste the key; no `set -x`; do not log request headers; redact `Authorization` in any HTTP trace. Check presence with `[ -n "$GROK_API_KEY" ]` and length with `${#GROK_API_KEY}`.
- Do not send private or personal data (30-day retention) and do not auto-merge anything on Grok's say-so.
- CI use needs a repository secret named `GROK_API_KEY`: adding it is Bryce's call (proposal only; `.github/workflows/**` is untouched here).
- Put a cap on loops: Tier 0 spend is unbounded without a Console budget limit.

The official Responses-API guide page I tried (`docs.x.ai/docs/guides/responses-api`) returned 404, so I could not confirm from xAI docs whether `GET /v1/responses/{id}` exists; even if it does, it needs a response id and Grok Build sessions do not publish one.
2. **`grok` CLI: not installed, not tested.** `https://x.ai/cli/install.sh` is reachable (HTTP 200; I read it without running it). Its header says auth is `GROK_DEPLOYMENT_KEY` or `~/.grok/auth.json` from `grok login`, i.e. a Grok login, not `GROK_API_KEY`; it installs under `~/.grok/` and its fallback host is `storage.googleapis.com/grok-build-public-artifacts`. Secondary sources (techdevnotes release notes, a tessl skill page, happier.dev) say `grok --resume <id>`, `grok sessions delete <id>` and `grok inspect --json` exist and that an `XAI_API_KEY` is accepted, but none says sessions sync across machines; the installer's `~/.grok/` layout suggests they are local to the machine that ran them. 3. **What is visible today:** `node tools/ci/fleet-bus.mjs read --last 200 | grep -i grok:` shows Fleet D's coordinator as `grok:DAD` (and `grok:dad`): HANDOFF, GAME-SLOT, GREEN and DONE posts, e.g. acting as orchestrator for Fleet B (02:59Z), lifting the Pages incident (03:07Z), reassigning PRs to D owners (03:10Z), launching D·IP1 to D·IP3 (04:31Z), releasing a GAME-SLOT (05:12Z), reporting #3483 merged (05:43Z), handing Fleet B back to Orchestrator A (05:57Z). ## Messaging DAD (Grok) from Claude sessions (follow-up from Bryce, 07:07Z)
Research only: web and docs, no installs, logins or paid calls. Dates read: 2026-10-22. Most Grok Build sources are third-party and say so.

**Short answer:** there is no documented xAI way to push a message into an already-running Grok session from outside, so no token Bryce can mint will do it. ### What works today, ranked by effort and safety
1. **Fleet bus** (zero setup, no token): `node tools/ci/fleet-bus.mjs send HANDOFF --to grok:<uuid|slug-hex> "..."` or `--to D` (fleet letter). `--to` accepts `grok:` addresses (see `ADDRESS_FORMS` in `fleet-bus.mjs`), and DAD already posts as `grok:DAD`, so it reads the bus. Latency is however often DAD polls it.
2. **PR comment** with the `fleet-status:` line on a PR DAD owns: zero setup, visible to Bryce, picked up when DAD watches the PR.
3. **Bryce relays by hand** (as the test did through his Claude account): safest, slowest, needs Bryce present.
4. **Headless `grok -p` from a machine with the CLI** using an `XAI_API_KEY`: starts a *new* paid session, needs an install (this container's installer run was blocked by the sandbox classifier), and cannot join DAD's context. Poor fit.
5. **Third-party remote control (Porte, AFK Pilot)**: only if Bryce wants phone control of his own sessions; not for Claude-to-DAD automation.

### Safety
- A holder of an xAI API key can spend Bryce's xAI credit and call every model and tool on the team; it does not expose his grok.com chats (the API has no chat-history endpoint). A `~/.grok/auth.json` login token is different: it is Bryce's account, so never copy it into the environment.
- Keep any such secret as an environment secret like `GROK_API_KEY`, never in the repo, `js/`, PR bodies or bus lines. Least privilege: use the bus (it grants nothing beyond the repo), and set a Console spend limit on any key that exists.
