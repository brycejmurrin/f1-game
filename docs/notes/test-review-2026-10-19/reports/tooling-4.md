**Debugger method (said once):** the js-debugger MCP lists Chrome page targets only (#2957), so I drove the Node inspector over CDP myself (`artifacts/test-review/tooling-4/cdp-bp.mjs`): `node --inspect-brk --experimental-test-isolation=none --test <file>`, `Debugger.setBreakpointByUrl` with condition `console.log('HIT#n'), false`, hits counted from `Runtime.consoleAPICalled`. Legend: **hit (cdp) file:line ×N** = condition fired N times in the real run. **hit (cov) …** = the test spawns a child process or uses a scratch copy, so I used `NODE_V8_COVERAGE` on the line's enclosing block (`cov-bp.mjs`; count = block executions across processes). **hit (cdp-vm) …** = module is `vm`-evaluated with a concatenated source, breakpoint set by scriptId after matching the source line (`cdp-bp2.mjs`). **hit (fn-cov) name ×N** = vm script with no resolvable line mapping; V8 function-name coverage (name-matched, weaker; collisions on common names such as `tick` are possible). **hit (py-trace)** = Python module, covered with `python3 -m trace --count` through a PATH shim (a JS debugger cannot break there). `n.a.` = nothing executes in the code under test (pure text scan), flagged as a finding. Breakpoints were set at the first body line of the named function; I took the function-level lines from the subagents and confirmed each really executes (hit counts above 0).
