### What is new in the method: two Node instruments that measure three itself

Earlier passes estimated three's per-object cost (A6: "15–35 µs per object, unmeasured"). This pass measured it.

| script (all in `hunt3/`) | what it does |
|---|---|
| `fakegl.mjs` | A no-op WebGL2 context (a Proxy) that counts every GL call and the bytes passed to `bufferData`/`bufferSubData`. |
| `bench-ro.mjs <N> <variant> <frames> <ch\|pl> [hidden]` | The REAL vendored r186 `WebGPURenderer({forceWebGL})` (the phone path) and the REAL `tsl-lit.js` material (`makeMaterial`, chunked or plain), with N meshes sharing one vertex buffer the way chunks do. | `bench-tex.mjs <N> <K> <obj\|shared>` | K sampled textures per draw, placed in three's per-object group or in `renderGroup`. Shared mode emulates the vendor patch B14 needs. |
| `bench-pass.mjs <P>` | The fixed CPU cost of one post pass: `QuadMesh.render` into a RenderTarget with a uniform write. |
| `census-tlx.cjs <track> <tod> <wx> <cam> <mobile> <steps> <frames>` | The REAL `game.js` in `tools/lib/game-vm.cjs`, with a gfx stub that reproduces TLX's record → render-object accounting per PASS: main, mirror (hooked in after boot), sun, car, lamp and lampStatic. Calibration: `bench-*` run on this container's x86 core, inside V8, over a no-op GL. The JS cost is real. The GL
driver and command-buffer cost of a real browser comes on top of it. About 12 % of the bench profile is the fake
GL's own Proxy overhead (`profsum.mjs`). For a phone, multiply by roughly 2–4×; that factor is an estimate, not a
measurement.

### (2) Deferred designs

#### F1 — repeated-draw coalescing (wheels and flaps), refined against the current code

**Which seam, and why the backend.** Hunt 2 proposed queueing in `car-draw.js` and flushing through
`updateInstances`/`drawInstanced`. A TLX-side seam is smaller and keeps GLX/WGX byte-for-byte unchanged:

1. **Producer flag.** Set `_wheelOpts.coalesce = true` (`game.js:6569`). Set it on the field's aero-flap opts
   bag as well (`game.js:1468`'s caller). `_mirWheelOpts` (`car-draw.js:1274`) gets the flag too. The ring opts
   (`_ringOpts`, alpha < 1) and every cockpit-rig draw (`frontsOnly`, `wScale ≠ 1`: a non-uniform axle scale)
   stay per record. Add `if (frontsOnly || ws !== 1) skip flag` at `car-draw.js:1164` by passing a second opts
   bag.
2. **TLX `draw()`** (`tlx.js:4415`): `if (opts && opts.coalesce && _coAppend(mesh.geo, model, mat, em, al)) return;`.
   `_coAppend` is a copy of `_decalAppend` (`tlx.js:2167-2186`) with three differences:
   - Runs are kept in `Map<geo, run>`, and the contiguity test is dropped. Any later record of the same
     (geo, mat, em, al) in the same pass appends to the run created at the FIRST record's slot. This is legal
     because the material is opaque with depthWrite, and three already sorts opaques by renderOrder.
   - The matrix is copied verbatim. There is no Z×X swap: unlike the decal quad, wheels have volume.
   - The material is `materialFor(opts, false, true)`, the existing `tlx-lit-instanced` family, plus
     `|ds`. It is resolved once per run.
   Runs reset where `resetRecs` runs: `begin`, `mirrorBegin` and `mirrorEnd` already null the sentinel records.
3. **Parity facts checked against the code.** The plain wheel draw takes per-chunk lamps only if
   `matU.lgRoad > 0.5`, which is the road alone (`tsl-lit.js:1752-1760`), so instanced (PC off) equals plain
   for wheels. The instanced fragment differs from plain only in `vertexColor * instanceTint` (white → equal)
   and in the road-marking `trk` read (wheels have hw = 0). Wheel matrices are `base × L` with L a rotation
   (`car-draw.js:1140-1146`), so det = +1. With an orthonormal matrix, three's instanced `transformNormal`
   equals `modelNormalMatrix`, and the identity `matrixWorld` gives the same front face as the per-record
   mesh.
4. **Capacity.** Today each run needs a padded InstancedMesh (`uboInstCap`, up to 1025 × 76 B ≈ 78 KB × ~55
   meshes ≈ 4.3 MB). **Build A2 first:** with attribute instancing a run is a plain Mesh, `count = n`,
   capacity 32 → 55 × 32 × 76 B ≈ 134 KB.
5. **Warm.** `warmFxPrograms` (`tlx.js:2368`) already warms one hidden blob run and one decal run. Add one
   hidden coalesced run per distinct wheel and flap vertex layout (`_layoutKey`, `tlx.js:2409`), both
   winding signs as the brake-ring lesson requires (§2aj point 3).

#### E4 — rain as a GPU box (no per-frame CPU or upload)

The drops already live in eye-relative wrap space (`particles.js:469-511`). Their world position is a pure
function of `(seed, t, eye)`: `rel = mod(seed*2R + v*t - eye + R, 2R) - R` with `v = (s*windX, -s, s*windZ)`. A
bottom wrap re-randomises x and z, which is `hash(seed, floor((seed.y*H - s*t)/H))`. The plan:

1. One static stream, uploaded at `rainSeed` (`:420`): per vertex `corner(2), seed(3), speed, len,
   alpha` = 8 floats × 6 vertices × N.
2. A new `fx.rainMat` (tsl-fx) whose vertex stage reproduces `rainFill` (`:514-553`): apparent velocity from a
   `camVel` uniform, the width axis via cross with the eye ray, `halfLen`/`halfW`/fade. The fragment stage is
   the particle ellipse.
3. `Particles.rainUpdate` keeps only `_camVel` and the shed count (draw range). `rainFill` disappears.
4. GLX and WGX need the same program (`glsl-fx`, `wgsl`). That is why this is M: three backends.

Gain: −108…156 KB × 2 copies + upload per frame, and ~50–150 µs CPU. The look is identical up to the hash
re-randomisation. Interim S (R9): wrap `_vertA` directly as the TLX stream's array. **Verify:** wet frozen A/B
on all three backends, `Particles.stats()` uploads → 0 per frame, census wet leg.

#### K3. `agent-view.spec.js` shared-page first-attempt flakes (night `lights.active` 0, `frame()` coverage undefined, `visible()` false)

**Root cause:** `load()` in tests/specs/agent-view.spec.js:28-36 returns before the race it asked for exists.
```js
await page.evaluate((id) => window.__apex.race(id), trackId);                      // fire-and-forget
await page.waitForFunction(() => window.__apex.info().track != null, …);           // TRUE AT ONCE on a reused page
```
`info().track` (apex.js:494) is `G.track.def.id` whenever `state` is race or count. On a reused page that is the **previous test's world**, so the wait passes immediately. `go()` + `jump()` then run against the old race, while `startRaceBody` for the new one is still awaiting `ensureScenery` / `ensureRaceSession` / `yieldMain`.

The pending start then does one of three things inside the test's window. All three are reproduced in `d3.cjs` / `d3night.cjs`:
1. **Nulls the world** (in-session switch: `dropTrackWorld`). Two frames after `load()` returned: `frame 2 track null state race`. Any hook read here sees no road, so coverage is undefined and `visible()` is false. K1's faults start, and on GLX the loop dies after 8.
2. **Re-grids the car.** `frame 41 track spa state count player s 6909.7 speed 0.0` undoes the test's `jump()`.
3. **Is cancelled by the test's own setting change.** The night test calls `setTimeOfDay("night")`, which changes `entrySettings()`. The pending start then rejects with "Race start settings changed" and **`quitToMenu()`** runs. `d3night.cjs`: `race promise rej Race start settings changed … state menu`. The scene being torn down to the menu within the two rAFs is a mechanism for `lights.active` 0. The VM still read 40 at the assertion because its timing differs, so that particular number is traced, not reproduced.

**Why the retry passes:** a fresh page starts in `state "menu"`, where `info().track` is null until the new race reaches `count`. So the wait is real there.

**Fix in the spec helper.** `race()` returns an awaitable (apex.js:35 `settled`) that resolves when *this* start reaches the grid. Await it, then give the new world one presented frame:
```js
async function load(page, trackId = "monza", frac = 0.05, speed = 60) {
  await boot(page);
  await page.evaluate(async (id) => { await window.__apex.race(id); }, trackId);   // async wrapper: CDP awaits native promises only
  await page.evaluate(([f, v]) => { window.__apex.go(); window.__apex.jump(f, v, 0); }, [frac, speed]);
  await page.evaluate(() => new Promise((r) => requestAnimationFrame(() => requestAnimationFrame(r))));
}
```
The "player not placed" test (agent-view.spec.js:59-61) uses the same race-then-wait pair and needs the same `await`.

**The spec fix alone is not enough.** While the awaited start builds, frames still tick with the previous test's `state === "race"`. `d3fix.cjs` on the unpatched tree: the loop dies (faults 8, `stopped`) and the race never settles. The K1 gate is required as well. With both, `d3fix2.cjs` is clean.

**Same flaw elsewhere (X1).** `fixtures.js` `pwSharedTest.loadTrack` (lines 495-501) does `race()` then `awaitTrackBuild()`. Its ready predicate is `info().track != null`, which is also true at once on a reused page. Exposed specs:
- camera-driving-hooks.spec.js: 23 `loadTrack` calls
- dev-tools
- logging
- smoke
- audio-smoke

Fix: start the race with
```js
window.__raceDone = null; Promise.resolve(__apex.race(i,t,w)).then(() => __raceDone = "ok", (e) => __raceDone = "err:" + e.message)
```

#### K4. `roundNormals` has never rounded a fused crown

**Intent.** Commit 7770ccc7b (2026-10-01), "track: round tree-crown normals so cone stacks light as soft volumes":
> The emitters' swayOff() runs it over the crown span swayOn() opened (every broadleaf, palm, cypress, stone pine, acacia, plane crown), and the scenery graph runs it for a swaying op on replay and on the canonical bake (instanced pines).

The commit was checked only on vertex counts and graph parity, plus a unit test on plain arrays.

**Why it never applied.**
- Fused props are emitted into `TrackModels.scratch()` accumulators (models.js:18-62). Those have no index access; the storage is `._data`.
- `makeAccum` already existed at 7770ccc7b (checked through `gh api …/contents?ref=7770ccc7b`). So from day one, `pos[i*3]` read undefined, and NaN normals were written as own integer keys onto the accumulator.
- Hunt 2 T2 made that no-op explicit (geom.js:59-61 early return).
- What did round: the graph's **canonical bake** (graph.js:109, plain-array `buf`, which feeds the instanced batches) and any plain-array stage.
- What did not: nature.js `swayOff` (295) and graph replay into `out` (graph.js:196).

**Consequence today: the same crown lights two different ways.** An *instanced* crown (GLX/TLX `createInstancedBatch`) gets rounded normals. A *fused* copy of the same model does not. That covers the fallback, `modelInst=0`, a key below `MODEL_INST_MIN_SAVED`, and backends or harnesses with no batch API.

Repro `lobed-accum.test.mjs` (was a scratch file) is a copy of tests/unit/lobed-trees.test.mjs with `out = TrackModels.scratch()`:
```
ACCUM=  fused-vs-canonical max |dn| = 0.0000   (plain-array fixture, what the test checks)
ACCUM=1 fused-vs-canonical max |dn| = 1.4490   (the production accumulator)
```

**Claims that it works:**
- docs/ARCHITECTURE.md:1710-1715 ("run by the emitters' swayOff() and by the graph's replay")
- build-props.js:705-706 ("Opt-in crown recipes require the same rounded normals in the fused fallback and canonical instance")
- tests/unit/lobed-trees.test.mjs:56-66 ("lobed crowns preserve canonical/fused normals"). It passes only because its fixture uses plain arrays, not the accumulator production uses.
- geom.js:50-58 (KNOWN GAP) and PERF-HUNT-2 T2 are the only places that say it doesn't.

**Gate.** The lobed-trees test on a scratch accumulator (`f.out.nrm._data`), graph-parity, verify-track md5 accepted deliberately, and a frozen GLX/TLX A/B of a tree-dense circuit.

#### K5. The menu's stepped pre-build is abandoned by SETTINGS / RACE! / chips

**Confirmed: the common flow builds the circuit up to three times.**
- Tile: `scheduleFlybyTrack(true)` (select-screen.js:764), generation N, starts `loadTrackStepped` after 400 ms.
- SETTINGS / NEXT: `openRaceSettings` *always* calls `scheduleFlybyTrack()` (race-settings.js:542). That bumps the generation, `current()` goes false, and `buildPaced` abandons at tracks.js:458 and frees the partial build. The new prepare starts the build again from zero.
- RACE!: `raceIntroFromSheet` / `introBuild` does `_menuGate.generation++` (js/game.js:3953 / 4060) and builds a third time.

Repro `d5.cjs` (VM, stepped user agent, real `scheduleFlybyTrack` / `openRaceSettings` / `raceIntro`, each tap 30 frames into a build):
```
build#1 start spa @f135
-- SETTINGS tap @f165 (build in flight: true)
build#1 ABANDONED after 31 frames
build#2 start spa @f215
-- RACE! tap @f245 (build in flight: true)
build#2 ABANDONED after 31 frames
build#3 start spa @f247
build#3 DONE after 43 frames
```
That is about 2.4 builds of work for one circuit. The PREPARING card waits for a full build instead of the remainder.

When the tile's build had already *finished*, SETTINGS hits the `_menuGate.ready === key` short-circuit and does not rebuild. The waste only happens when a tap lands mid-build, which is the normal case for a player who taps tile → NEXT → RACE! within a few seconds on a phone.

**Also wasteful:** `menuKey` (js/game.js:2341) includes `raceWeather`. The build depends only on `sessionDarkFor(def)` and `fieldSize()` (`trackBuildOpts`). So a weather-chip tap (race-settings.js:340), and a day↔default tap on a day circuit, abandon an in-flight build of an identical world.

**Stale `_menuGate.ready`: none found.** `menuWorld()` also requires `_menuGate.track === track`. `dropTrackWorld` / `loadTrack` clear `ready`. A same-circuit tod change keeps the old world with its old key, which `menuWorld()` correctly rejects. `startRaceFromSheet` stamps `ready` only when id, night and slots match.

**Fix sketch.**
- Key the build by `[idx, sessionDarkFor(def), fieldSize()]` (a `buildKey`) and keep the in-flight `loadTrackStepped` promise in `_menuBuild = { key, promise }`.
- In `scheduleFlybyTrack`, if `_menuBuild.key === buildKey(want)`, do not bump the generation. Let `current()` compare `buildKey` instead of raw tod/weather.
- In `introBuild`, `await _menuBuild.promise` when the keys match, instead of `generation++` and a rebuild.

This is hunt-2 T3's "join". Its risk is that a late caller receives the world the join hands back, so assert `track && builtTrackId === def.id` after the await.

**Gate.** `d5.cjs` as a VM unit test asserting one `buildPaced` start for tile → SETTINGS → RACE! on an unchanged world. Then garage-prebuild / garage-out-before-card specs.
