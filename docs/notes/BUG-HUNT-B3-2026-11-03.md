## Found, not fixed here

- **`dispatch.yml` trust comment (med, design).** It says "`ref:` pins the deploy branch, so a PR's edit of
  dispatch.yml never runs here". `ref:` pins only the checkout. On `pull_request` events GitHub runs the workflow
  file from the PR's merge ref, with `WORKER_FIRE_*` secrets. Same-repo branches only, single owner. A fix moves
  those triggers to `pull_request_target` or gates the fire step on the event, and that changes the dispatcher's
  trigger model. Left for a dispatcher-owned change.
- **`guards-verdict.mjs` cache key (low).** The key is `git write-tree` (the index) and the dirty check covers
  tracked files only. An untracked file added after a green `run` keeps the 10-minute hit live.
- **Foundation specs `geometry.every(e => e.ok)` (low, plausible).** There is no length floor in about 20
  `*-foundation.spec.js` files or `new-hooks.spec.js`. `__apex.geometryDiagnostics()` returning `[]` would be
  vacuous. Not changed: it is a broad browser-spec diff, and I could not show the empty case happens.
- **`tooling-fast` fallback (low).** When `merge-base` fails it narrows to `HEAD~1`, then to `[]` (exit 3 "empty
  diff"), so a git failure reads as "nothing changed".
- **`deploy.mjs` `--name-only` sites (low, contrived).** At :492, :715 and :1048 a rename's source is not listed
  (ledger M36).
