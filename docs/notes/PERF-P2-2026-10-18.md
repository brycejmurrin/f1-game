### 1. Dialog `:has()` scope

Every shell `<dialog>` is a `<body>` child; the one built at runtime (the Data Hub telemetry popup,
`js/data/telemetry.js`) is appended to `#datahub`. So the two rules split into a body-child form and a
`> :where(#datahub) > dialog` form, the same match; `:where()` keeps specificity.

Body-restyle micro-bench (`scratch/p2/bench.mjs`): in the live phone-shape race page, toggle `body.hud-tyre-stack` (the
class the HUD fit flips) 300 times, each followed by a `getComputedStyle` read; interleaved base/new, 3 pages each:

| arm | p50 ms | p90 ms | mean ms |
|---|---|---|---|
| base | 3.7, 3.7, 4.0 | 5.6, 4.2, 5.7 | 4.10, 3.83, 4.31 |
| scoped | 2.2, 2.2, 2.2 | 2.5, 3.1, 2.5 | 2.22, 2.36, 2.26 |

A body attribute that only an attribute-presence rule reads (`data-radio-corner`) costs 0.1 ms in both arms, so the gap
is the body-subject `:has()` re-match, not the bench. The per-frame trace mean dilutes it (body restyles on about a third
of frames): quiet-box pair 2.03 → 1.61 ms/frame of `UpdateLayoutTree`; the other two pairs ran beside the commit hook's
guard suite and are not comparable.

### 2. Root `:has()` invalidation from text writes (round 2)

Invalidation tracking (`INV=1`, `disabled-by-default-devtools.timeline.invalidationTracking`) on the same race: about
**175 `:has()` invalidations a second each on `<html>` and `<body>`** (~3 a frame), and body restyled as "Affected by
:has()" ~86 times a second. The stack of most of them: `hText` (`js/ui/hud.js:76`) → `paintInstruments` → `updateHud`,
i.e. `el.textContent = v` on the speed digits every frame; the rest are the `fitHud` root-variable writes (#2797).

**Refuted: the two remaining descendant `:has()` rules.** `body:has(.dock .touchbtn:not([hidden]))` (hud.css) and
`body:has(:is(#home-motion, #install-chip):not([hidden]))` (menu-destinations.css) were scoped to exact child chains
and A/B'd (3 interleaved pairs, invalidation tracking on): root `:has()` invalidations 176/157/172 → 172/169/175 per
second, style recalc 2.32/1.65/2.27 → 2.38/2.25/1.94 ms/frame. No change; reverted, not shipped.

**One-page CSSOM bisect** (`scratch/p2/bisect.mjs`: consecutive 4 s windows, rules deleted cumulatively):

| rules removed (cumulative) | rules | style recalc ms/frame | root `:has()` invalidations/s |
|---|---|---|---|
| none | 0 | 2.84 | 195.5 |
| `:empty` | 12 | 1.56 | 82.5 |
| + body/html-subject `:has()` | 48 | 0.92 | 88.5 |
| + every `:has()` | 56 | 0.25 | 0 |

So the trigger is emptiness: `textContent = v` removes the old text node and inserts a new one, the element passes
through `:empty`, and Blink re-checks the `:has()` rules up to the root (`.hud-gaps:not(:has(> div:not(:empty)))` is
the one rule that mixes the two). Proposed fix: `hText` writes `firstChild.data = v` when the element holds exactly one
text node (a character-data change, no child-list mutation), keeping `textContent` for the first write and for "".
`js/ui/hud.js` is in open PR #2803's file set: asked the orchestrator for a one-function exception.
