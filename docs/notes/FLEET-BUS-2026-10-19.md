# Fleet bus and merge lease (2026-10-19)

Bryce, 2026-10-19, asked who should hold merges (Claude ORCH, Cursor's DAD, or
split): "Consider I want to be able to run from any and have them commiunicate".
So merging belongs to a **lease** any host can take, and messages go on a
**bus** any host can read. Tool: `tools/ci/fleet-bus.mjs`; tests:
`tests/unit/fleet-bus.test.mjs`.

## The incident it closes

On 2026-10-19 Cursor's DAD and a Claude ORCH both merged, each pacing "one merge
per green Pages run" on its own (#2839, #2955 and #2970 landed beside ORCH's
queue). AGENTS.md named "Grok Bot" as the sole merge holder, and no Grok
activity showed in the 48 h before. A rule that names a host fails whenever that
host is not running, and nothing stopped a second merger.

## Design: one branch, `claude/fleet-bus`

- **The lease is the branch's tree.** `lease.json` is
  `{holder, since, expires, ttlMin, note}`. `{}` means free.
- **The bus is the branch's commit log.** Each commit subject is one line:
  `<TYPE> to:<address> from:<host>:<id> <text>`. TYPE is one of READY, GREEN,
  BLOCKED, HANDOFF, DONE, INCIDENT or LEASE. The address is a role
  (`orchestrator`, `merge-holder`), `#<PR>`, a `<host>:<id>`, or `*`. Every
  lease change writes its own LEASE line, so the log also records who held the
  lease and when.
- **Every write is a fast-forward push**, and that is the compare-and-swap.
  Git refuses a branch update that does not fast-forward: "only fast-forward
  updates are allowed, which means the destination must be an ancestor of the
  source commit" (<https://git-scm.com/docs/git-push>, PUSH RULES). The writer
  fetches, decides on the lease it fetched, commits on top of that tip and
  pushes. When two hosts race, the loser's push is rejected, so it fetches
  again and decides again on the winner's lease. The unit test runs this race
  against real git, and a force-push mutation makes it fail.
- **Why a `claude/*` branch.** It is the one write every host has. In the
  Claude cloud container the proxy accepts pushes to `refs/heads/claude/*` only
  and refuses most of the REST API (measured; who-is-on-it.mjs header). Cursor
  agents already push to `claude/claims-board`. Codex and Grok have git and
  `gh`. An issue comment or a label has no precondition on its write, so two
  hosts could both "acquire" through it.
- **Expiry.** The default TTL is 60 min, clamped to 1–240. The holder renews on
  every tick. A dead holder's lease lapses, and anyone may then take it or
  clear it. `break --grant "<the user's words>"` takes a live lease only on a
  user grant, and its LEASE line records that grant.
- **The refusal.** `lease check` exits 0 only when the caller holds a live
  lease. The merge holder runs it before every merge (role-merge-holder.md). A
  second host that is not the holder gets exit 2 and does not merge.
- **Wake cost.** `read` fetches one small branch and prints only the lines after
  the saved cursor (`artifacts/fleet-bus/cursor-<id>.txt`; `--since <sha>`
  overrides it), then one `= bus N new, cursor <sha7>` line. If the cursor is
  missing or unknown, it prints the last 20 lines. Read once per tick and never
  in a loop.

## Per host

| host | lease and send | read | fast path kept |
|---|---|---|---|
| Claude cloud | `node tools/ci/fleet-bus.mjs …` (identity `claude:<CLAUDE_CODE_SESSION_ID>`) | `fleet-bus.mjs read --to <role> --to '#<PR>'` once per wake | `send_message` to Claude peers. Mirror anything another host needs onto the bus |
| Cursor (DAD, cloud agents) | the same CLI with `--as cursor:<agent id>` or `APEX_FLEET_AS` (git push to `claude/*` works: its claims are on `claude/claims-board`) | the same; `subscribe_timer` ticks | PR comments, which stay the per-PR record |
| Codex | the same CLI with `--as codex:<CODEX_THREAD_ID>` (git and `gh`) | the same, one read per task step | none |
| Grok (Build or Bot) | the same CLI with `--as grok:<bot>` on the machine it runs on | the same | none |
| GitHub MCP only (no shell) | `get_file_contents` `lease.json` at `refs/heads/claude/fleet-bus` (the reply carries the blob `sha`). Decide with the rules above, then `create_or_update_file` on `lease.json`, branch `claude/fleet-bus`, with that `sha` and the LEASE line as the commit message. The Contents API needs "the blob SHA of the file being replaced" and lists 409 Conflict (<https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents>). Not yet measured live: that a stale `sha` returns 409 | `list_commits` `sha: claude/fleet-bus`, `since: <ISO time>` (<https://docs.github.com/en/rest/commits/commits#list-commits>) | — |

Unauthenticated REST reads work from the cloud container but are capped at 60
per hour (<https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api>),
so the CLI reads through git, which has no such cap.
