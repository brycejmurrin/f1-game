## GLX iPhone black canvas: new leads (research, no device)

Bryce's answer was "Find more potential issues", so a research pass read the GLX post chain against ANGLE-Metal's
FrameBufferMtl.mm. The new lead: on a phone every post target is a square cover target, but passes draw only into the
w×h viewport. GLX invalidates the whole FBO, which ANGLE-Metal turns into DontCare load and store, so on Apple's tile
GPU the area outside the viewport holds undefined memory. In RGBA16F that can decode as NaN. The bloom, godray and
SSAO taps read above the rect without a clamp, and the Karis weight carries NaN through the mips, which shows as black.
TLX clears each target and never invalidates, which fits "TLX works". A second, certain bug: cover-mode texel offsets
are logical, so the vertical taps are about 2.16 texels long. Also: the #4250 Web Inspector A/B disables every
invalidation, so it cannot tell WebKit 280799 from this lead. The FBO-only patch (skip invalidations while an FBO is
bound) separates them. Sources: https://raw.githubusercontent.com/google/angle/main/src/libANGLE/renderer/metal/FrameBufferMtl.mm,
https://raw.githubusercontent.com/google/angle/main/src/libANGLE/renderer/metal/DisplayMtl.mm,
https://bugs.webkit.org/show_bug.cgi?id=281763.
