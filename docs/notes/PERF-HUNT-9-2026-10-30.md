### GLX cover-target fix (`js/render/glx/post.js`)
On the phone cover path a post target is now CLEARED at pass start (a loadAction Clear on a tiler, as TLX does)
instead of invalidated, so nothing outside the w×h rect is undefined. Tap texels are now physical (1/alloc): on a
phone, bloom, AO blur, godray blur and FXAA return to their intended spread. That is a visual change, and it applies
only on GLX. Desktop: the recorded GL call stream hashes identically to the old post.js (Chrome and Mac Safari UAs,
three option sets). Tests: `glx-output-target` (cover targets are cleared and never DontCare'd; desktop keeps the
hint; physical texels). Left alone: SSR/sharpen `uReflTexel` (it carries the aspect ratio), and an existing
cover-mode bug: SSAO and contact-shadow view reconstruction read vUV as screen UV.

## GLX iPhone black canvas: new leads (research, no device)

Bryce's answer was "Find more potential issues", so a research pass read the GLX post chain against ANGLE-Metal's
FrameBufferMtl.mm. The new lead: on a phone every post target is a square cover target, but passes draw only into the
w×h viewport. GLX invalidates the whole FBO, which ANGLE-Metal turns into DontCare load and store, so on Apple's tile
GPU the area outside the viewport holds undefined memory. In RGBA16F that can decode as NaN. The bloom, godray and
SSAO taps read above the rect without a clamp, and the Karis weight carries NaN through the mips, which shows as black.
TLX clears each target and never invalidates, which fits "TLX works". A second, certain bug: cover-mode texel offsets
are logical, so the vertical taps are about 2.16 texels long. Also: the #4250 Web Inspector A/B disables every
invalidation, so it cannot tell WebKit 280799 from this lead. The FBO-only patch (skip invalidations while an FBO is
bound) separates them. Sources: https://raw.githubusercontent.com/google/angle/main/src/libANGLE/renderer/metal/FrameBufferMtl.mm,
https://raw.githubusercontent.com/google/angle/main/src/libANGLE/renderer/metal/DisplayMtl.mm,
https://bugs.webkit.org/show_bug.cgi?id=281763.

## Device checks for Bryce
1. GLX, live build: does the canvas render? Copy the `?gfxdebug=1` line. To separate the two leads on the OLD build:
   Web Inspector before boot, `const o = WebGL2RenderingContext.prototype.invalidateFramebuffer;
   WebGL2RenderingContext.prototype.invalidateFramebuffer = function (t, a) { if (this.getParameter(this.FRAMEBUFFER_BINDING)) return; return o.call(this, t, a); };`
   (skips only FBO invalidations). If that alone cures it, the cover-target lead was the cause, not WebKit 280799.
2. Listening pass: `?lab=rivalEps,audioIdle` (pass-bys, menu → race → pause → resume, lock and unlock).
3. `?lab=tlxLite` only matters when TLX falls back to WebGL2 (`three api=webgl2`); `?lab=aiLod` needs a reload.
